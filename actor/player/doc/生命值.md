# 生命值

`actor/player/src/ink_health.gd`：Player 的子节点 `InkHealth`，玩家「血量」的**单一真源**。
数值就是墨水：每种墨水各一本账，0 = 空瓶（液面见底），max_ink = 每种墨水各自的满瓶量。

墨水有几种由 `ink/src/ink_palette.gd` 的 `INKS` 决定；**加一种墨水这里不用改**。

## 接口

- 查询：`ink_of(材质 id)` / `max_of(材质 id)` / `ratio_of(材质 id)`（该色 0..1 的液面比例）。
- 合计：`ink` / `ratio()` 仅供统计；HUD 与瓶身生命液面读取黑墨自己的 `ink_of()` / `ratio_of()`。
- 增减：`add(材质 id, amount)` / `reduce(材质 id, amount)`，自动夹在 0..max_of。
- `signal changed`：只在数值真的变了时发一次（被夹住也算变）。
- 直写 `ink = x` 只改显示用的合计值，不动各色账本 —— 游戏内不要那么写。
- `max_ink` 是**每种墨水的**上限，**每关不一样就改场景里这一个数**（`player.tscn` 现在是 20000/色）。

## 谁在用它

- `BottledInk`（`actor/player/src/bottled_ink.gd`）：每帧拉黑墨 `ratio_of()` 当液面比例，图层自己不再存 `fill`；
  液面比例 × `capacity_mass` 进合成质量，见 `actor/player/doc/墨水.md`。
- `ui/hud/src/hud.gd`：`health_path` 指过来，`changed` 一响就显示黑墨的比例和像素数。
- 画布（`actor/canvas/src/canvas_surface.gd`）：这里的数值**就是 px**，画一个空像素按**当前选中的墨水** `reduce(id, 1)`、
  擦掉一个有墨像素按**那个像素原来的颜色** `add(id, 1)`、重绘把画布上剩的全还回来、固化不还。
  所以 `max_ink` 是「每种墨水能装多少个像素」。
  钉子不是墨水，落钉子既不扣也不还。
- 碰撞伤害由 `actor/player/src/player_physics.gd` 的 `apply_collision_damage()` 接入
  `damage()`；按材料伤害预算换算成等效受损像素，再乘 `ImpactDamage.player_damage_multiplier`
  （默认 100），只扣黑墨，不改变材料破坏。`collision_damage` 仅作累计调试统计。
- `Player.collision_damaged(amount, impacts)` 是受击表现接口；每个 impact 带世界坐标、外法线、
  单次伤害、冲量和攻击材质，可直接连接溅血粒子节点。
- 黑墨从正数降到 0 时触发 `InkHealth.depleted`，由 `FallDeath` 进入现有死亡/复活流程；
  复活补满黑墨，灰、红、黄墨仍保留各自独立账目。

## 为什么不放在 BottledInk 里

液面是**表现**，生命值是**数据**：以后质量/质心微调、伤害与拾取都要读它，
而墨水图层可能换成别的表现。所以真源单独一个节点，图层与 HUD 都只是消费者。
