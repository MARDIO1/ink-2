# 安全脱困

ESC 的“脱离卡死”只使用当前关卡已经过的出生点/复活点，按最近激活的顺序优先尝试，最多尝试八次提交。
没有标记时使用本关初始位置。普通死亡直接返回最后激活点；脱困仅在该点及周围无法安全站立时，才尝试更早激活的点。
落地激活、双层区域及编辑设置见 [复活点](checkpoints.md)。

每个目标先尝试原位，再逐层检查附近左右和上方，搜索步长按玩家实际碰撞体高度计算。
复用 PixelWorld 已烘焙的像素贪心矩形，包围盒筛选附近物体，再用 OBB/SAT 检查身体及复位后的手掌空间。
下方 96 像素内必须有实际实心像素支撑；不移动、不删除地形、碎屑、怪物或物品。

单次搜索最多 192 个候选、30000 对矩形检查；按约 2 毫秒软预算分帧。
预算在检查批次间检查，不保证每帧严格小于 2 毫秒；不重建碰撞，不遍历整张地图像素。
搜索时暂停世界并锁定菜单按钮，保持 UI 事件循环，防止重复请求或中途换场景。

传送后等待一帧重新读取附近物体并复查；恢复游玩后的首个实际物理步再检查一次。
此时若被移动物品占据，自动再搜索一次，并跳过上一落点；仍失败则打开 ESC、保持暂停、显示提示。
首次搜索找不到安全位置时玩家保持原位置；搜索中提交的落点复查失败时回退原位置。

测试：`test/test_safe_spawn_search.gd`（16 项，含 200 碎屑场景）、`test/test_escape_stuck.gd`、`test/test_hud_exit_menu.gd`。
200 碎屑构造场景一次实测搜索 35 个候选，分为七次让出 UI 帧，找到安全点；此数据不是所有地图的耗时保证。
