# 创造模式架构

本文件是 `debug/creative` 的边界契约与迁移计划。改这个模块之前先读它。

## 现状（2026-10-18 实测）

| 文件 | 行数 | 现在负责什么 |
| --- | --- | --- |
| `src/creative.gd` | **2965** | 输入、工具状态、对象增删、拖动、角色暂停、保存、重载、UI 装配 |
| `application/editor_session.gd` | 32 | 交互态字段（模式/拖动/选中），**行为仍全在 Creative** |
| `application/editor_commands.gd` | 253 | 撤销命令端口，实现仍回调 Creative |
| `application/editor_history.gd` | 70 | 时间线（已独立，可直接保留） |
| `ui/src/editor_palette.gd` | 590 | 右侧面板，只 emit 动作（保留） |
| `ui/src/editor_save_view.gd` | 167 | 保存表单（保留） |
| `actor/canvas/src/canvas.gd` | 1387 | 画布行为 + 工具栏构建 + 布局 |
| `actor/canvas/src/canvas_surface.gd` | 1992 | 输入、绘制、选区、纹理、快照 |

两个已经量出来的硬事实：

- **29 个测试文件、273 处 `creative._…` 私有访问**。重构必须先给测试一条明确入口，
  否则只能拆出"多个互相依赖的文件"。
- **蓝图核心反向依赖 HUD**：`blueprint_codec.gd:5` preload 了
  `ui/hud/blueprint/src/blueprint_store.gd`，只为了 `VERSION` / `MAX_SIDE` / `validate`
  （:38、:41、:268、:508）。数据格式因此被锁在 UI 目录里。
- **保存夹带生成**：`export_map_to()` 里先 `_map_canvas.generate(false)` 再
  `_sync_node_transforms(scene)`。保存同时承担了生成、状态转换和序列化。

## 一、三种状态必须分开（比减少行数更重要）

| 状态 | 内容 | 归属 | 谁能写 |
| --- | --- | --- | --- |
| **编辑结果** | 像素、部件位置、轴承连接、地图配置 | 场景节点 + 快照 | 功能工具、保存模块 |
| **运行时状态** | 模拟后的旋转/受力/断裂、临时物理引用 | 物理世界 | SimulationRuntime |
| **界面状态** | 当前工具、悬浮、选框、窗口、预览 | session / ui | 输入与视图 |

保存规则（写代码前定死）：

1. **默认只保存编辑结果**。运行的姿态不落盘。
2. 需要保存"模拟之后的姿态"时，必须是**显式操作**（独立按钮/命令），不能藏在普通保存里。
3. `generate()` 是运行时动作，不是编辑动作。保存路径里调用它必须能被指出理由，
   且不得追加撤销步骤（当前 `generate(false)` 已是这个语义，保留但要显式化）。
4. 加载后的连接恢复统一走项目已有的 **`body_bake_completed` 屏障**；
   零件不得自己猜"依赖到了没"。

## 二、目标结构

`creative.gd` 保留原路径与场景入口，最终只做四件事：**装配编辑器、进出编辑模式、
分发未被 UI 消费的输入、协调当前工具/关卡/历史**（目标 400–600 行）。

| 模块 | 职责 |
| --- | --- |
| `application/editor_session.gd` | 当前工具、选中对象、进行中的拖动；终态与取消语义 |
| `application/editor_history.gd` | 时间线（保持不动） |
| `application/editor_save.gd` | **新增**：快照、自动保存、导出；唯一允许 `generate` + 序列化的地方 |
| `features/layout_tools.gd` | 画布 / 出生点 / 复活点 / 传送门 / 墨泉 |
| `features/monster_tools.gd` | 小怪放置、删除、移动、缩放 |
| `features/dialogue_tools.gd` | 对话触发点 |
| `features/map_text_tools.gd` | 地图文字 |
| `features/image_tools.gd` | 图片导入与编辑 |
| `ui/` | 按钮、面板、表单：只提交动作、展示结果 |

## 三、解耦契约

1. **视图不碰文档**：`ui/` 只持有控件、`emit action_requested`、经显式 `Callable` 询问。
2. **时间线只有一处**：撤销栈只在 `editor_history.gd`，功能工具不得自建历史。
3. **功能模块不得持有 Creative**。入参是「关卡 + session + record/undo 回调」。
   出现 `get_parent().get_node("Creative")` 这类反向抓取即视为违约。
4. **保存是唯一出口**：`editor_save.gd` 之外不得调 `generate()` / `export_map_to()` /
   `request_snapshot()`。
5. **一次用户操作 = 一个可撤销事务**。不能出现"编辑器撤销了对象，画布却留着像素"。
6. **模式常量单一真源**：`application/editor_modes.gd`。
7. **蓝图核心不依赖 UI**（详见 `actor/canvas/blueprint/doc/架构.md`）。

## 四、迁移计划（每阶段可独立合并）

顺序按风险与收益排：**先基线，再保存，再拆功能，然后蓝图，最后画布**。

| 阶段 | 做什么 | 门禁 |
| --- | --- | --- |
| **P0 ✅** | 模式常量收成单一真源；删死转发 | 编辑相关测试 |
| **P1 ✅** | 19 个交互态字段搬进 `editor_session.gd` | 8 个编辑测试全绿 |
| **P2 ✅** | 回归基线 `test/tools/baseline_editor.gd`（19 条断言）：路由加载 → 蓝图采集/放置/撤销/重做 → 固化 → 导出/重进 | 见下方命令 |
| **P3** | 抽 `application/editor_save.gd`：快照/自动保存/导出，先搬行为再谈改进 | 保存后重进结构一致 |
| **P4** | 抽 `features/layout_tools.gd`（当前最大一块） | picking / layout / portal / spawn-respawn |
| **P5** | 抽 monster / dialogue / text / image，逐项迁移 | 对应测试逐项转绿 |
| **P6** | 蓝图核心搬出 HUD，补连接保存与放置事务 | `test_blueprints` / `test_blueprint_ui` |
| **P7** | 拆 `canvas.gd`（工具栏/输入/表面/固化），测试转向新入口，删兼容代理 | 全部 `test_*` |

### P2 基线怎么跑

```powershell
& 'D:\Godot\Godot_v4.7.2-stable_win64_console.exe' --headless --path D:\Ink `
  --script res://test/tools/baseline_editor.gd
```

19 条断言，headless 约 3–5 分钟（导出场景最慢）。只读现有地图，只写 `user://baseline_export.tscn`
并在结束时删除。

**建立基线时发现的两条顺序约束**（后续拆 `editor_save` 必须遵守）：

1. `generate()`（固化）会把画布像素转成刚体**并清空画布**，所以蓝图采集/放置/撤销必须
   发生在固化**之前**——先固化再采集只会得到 0 像素的空蓝图。
2. `BlueprintCodec.place()` 返回的是**错误字符串**，空串才是成功；用 `is_empty()` 判断
   会把"失败但有错误文本"误判成成功。

### P1 的三条实测经验（别重复踩）

1. **`layout_drag_target` / `selected_control_target` 必须保持无类型**：它们既装 `Node2D`
   也装 `Control`（`MapTextLabel`）。标成 `Node2D` 会报 `Invalid assignment … 'Label'`，
   **而测试仍然是绿的**，错误只在 stderr。看结果必须看 stderr。
2. 机械改名是**编译期可校验**的：先跑 `--check-only`，比直接跑测试快得多。
3. **统计跨模块引用必须递归**：PowerShell 的 `**` 不是递归通配符，
   曾因此漏掉 `ui/cursor/src/game_cursor.gd` 对 `_dragging_monster` 的读取。

## 五、验收标准（不只看"能转"）

- 经过真实 `Root` 加载流程后，轴承与连接完整。
- 保存 → 退出 → 重新进入，装置结构一致（像素、部件位置、连接、配额）。
- 蓝图：放置 → 撤销 → 重做后，连接与墨水数量一致。
- 切换工具、窗口失焦、切关时，拖动能被正确取消（无残留 session 状态）。
- UI 点击不穿透到画布。
- 每个阶段都跑 `--headless --check-only` 并检查 stderr。

## 六、不做的事

- 不推倒重写，不引入 Manager / Service 之类的新抽象。
- 不为了行数拆文件；验收是"职责清楚、保存可靠、能独立验证"。
- 不把地图、蓝图、撤销强行统一成一种大存档格式——可以共用采集/恢复函数。
- 不在同一提交里既搬文件又改行为。
