# 创造模式架构

本文件是 `debug/creative` 的装配契约与迁移计划。改这个模块之前先读它。

## 现状（2026-10-17 实测）

`src/creative.gd` **2924 行**，10 个 `#region`。已经有人开始拆，但只拆了一半：

| 文件 | 行数 | 现在是什么 |
| --- | --- | --- |
| `application/editor_history.gd` | 70 | 纯时间线（RefCounted，信号 + 撤/重做栈） |
| `application/editor_commands.gd` | 253 | 文档命令适配器，只拿显式端口字典 |
| `ui/src/editor_palette.gd` | 567 | 右侧面板视图，动作全部 `action_requested` 转发 |
| `ui/src/editor_save_view.gd` | 167 | 保存表单视图，只留一个 `save_scene` 写入端口 |
| `src/creative.gd` | 2924 | **其余全部** |

### 六个具体问题（都有证据，不是主观感受）

1. **单文件仍承载 6 个功能域**：出生点/复活点/画布/传送门/墨泉（734 行）、小怪（555）、
   地图文本（193）、地图图片（183）、导出地图（316）、生命周期与输入（316）。
2. **`#region` 已经漂移**：撤销/重做（`_record_edit`、`undo_last_edit`、`_capture_redo_data`）
   被写进「地图图片」区；墨水配额表被写进「小怪放置」区。分区注释不可信 = 读者只能通读全文。
3. **状态用 16 个负整数编码 4 个互不相关的功能族**：
   `MONSTER_MODE_*`、`DIALOGUE_MODE_*`、`TEXT_MODE_*`、`LAYOUT_MODE_*`，外加一个 `CONTROL_MODE`，
   全部塞进同一个 `_monster_mode`。`_handle_layout_mouse_button` 因此变成 108 行的四层 match。
4. **`creative.gd` 有约 200 行只为测试存在的属性代理**（`_editor_ink_buttons`、`_gear_button`、
   `_layout_buttons`、`_ink_quota_fields`、`_monster_buttons`…），全部 `return _palette.xxx`。
5. **模式常量在 palette 里复制了一份**（`editor_palette.gd:8-18`），两份可能各自漂移。
6. **20 个测试文件、约 90 个成员直接依赖 `creative`**，绝大多数是 `_private` 名字。
   这是重构真正的堵点——不是代码，是测试。

## 目标结构

```
debug/creative/
├─ creative.gd                 组合根：生命周期 + 输入路由（目标 < 600 行）
├─ application/
│  ├─ editor_history.gd        时间线（保持不动）
│  ├─ editor_commands.gd       文档命令端口（保持不动）
│  ├─ editor_session.gd        模式状态机（替代那个 int + 16 个常量）
│  └─ editor_world.gd          关卡文档读写：节点查找/创建/命名/容器
├─ features/
│  ├─ layout_tools.gd          出生点 / 复活点 / 游玩画布 / 传送门 / 墨泉
│  ├─ monster_tools.gd         小怪放置、删除、缩放、编辑拖动
│  ├─ dialogue_tools.gd        对话触发点 + 输入窗
│  ├─ map_text_tools.gd        文本放置 + 输入窗
│  ├─ image_tools.gd           导入图片的放置与删除
│  └─ ink_quota.gd             关卡墨水配额（数据 + 应用）
├─ ui/                         视图层（只 emit 动作，不碰文档）
└─ doc/
```

预估：`creative.gd` ≤ 600；`layout_tools` ≈ 500；`monster_tools` ≈ 450；其余每个 150–250。

## 解耦契约（写代码前必须遵守）

1. **视图不碰文档**。`ui/` 里的脚本只允许：持有自己的控件、`emit action_requested`、
   通过显式 `Callable` 端口询问（例如 `query_ink_quota`）。不得直接 `level.add_child`。
2. **文档命令只走端口**。`editor_commands.gd` 的 `REQUIRED_PORTS` 是白名单；
   新增一种可撤销操作 = 加一个端口 + 在 `creative.gd` 实现，不许绕过。
3. **时间线只有一处**。撤销栈只存在于 `editor_history.gd`；功能工具不得自建历史。
4. **功能工具只操作「关卡 + 编辑记录」**：入参是 `level` 与 `record_edit` 回调，
   不持有 `_map_canvas`、不碰 UI 节点。
5. **模式收敛到一个对象**。`editor_session.gd` 暴露 `tool_kind` + `payload`，
   取代 16 个负数常量；输入路由按 `tool_kind` 分发，不再写四层 `match`。
6. **常量单一真源**。模式常量只保留在 `editor_session.gd`，palette 从它 preload。

## 迁移计划（每阶段可独立合并）

**顺序是"先拆状态，再拆功能"**，不是反过来。原因是实测依赖：`layout_tools` 那 734 行要用到
`_level_root / _map_canvas / _record_edit / _refresh_layout_overlay / _layout_drag_* /
_selected_control_target / _selected_portal / _canvas / _new_canvas_size / _portal_*` 约 15 项状态。
先抽功能就得开 15 个端口——比现在的上帝对象更糟。先把状态挪进 `editor_session`，
功能模块拿一个 `session` 就够了。

| 阶段 | 做什么 | 门禁 |
| --- | --- | --- |
| **P0 ✅** | 单一真源：模式常量收进 `application/editor_modes.gd`；删掉死转发 | 编辑相关测试 |
| **P1 ✅** | `application/editor_session.gd`（32 行）：19 个交互态字段搬出 `creative.gd` | 8 个编辑测试全绿 |
| **P2** | 抽 `features/layout_tools.gd`（734 行里最大一块） | picking / layout / portal / spawn-respawn |
| **P3** | 抽 `monster_tools` / `dialogue_tools` / `map_text_tools` / `image_tools` | monster-drag / monster-resize / image-import |
| **P4** | 测试改指向新入口，删掉 `creative` 上的转发层与属性代理 | 全部 `test_*` |

### P1 的两条实测经验

1. **`layout_drag_target` / `selected_control_target` 必须保持无类型**。它们既装 `Node2D`
   （画布、传送门、齿轮），也装 `Control`（地图文本 `MapTextLabel`）。当初给它们标 `Node2D`
   立刻出现 `Invalid assignment ... with value of type 'Label'`——测试还是绿的，只在 stderr 里报。
   **看测试结果也要看 stderr**。
2. 改名是**编译期可校验**的：`_session` 一旦没声明，`var x := _session.foo` 之类会连锁报
   "cannot infer type"。所以这类机械迁移先跑 `--check-only` 比直接跑测试快得多。
3. **统计跨模块引用必须递归**。`Select-String -Path 'D:\Ink\**\*.gd'` 里的 `**` 不是递归，
   只匹配一层目录，因此漏掉了 `ui/cursor/src/game_cursor.gd` 对 `_dragging_monster` 的读取。
   症状是进地图编辑器后每帧报 `_uses_ring: Invalid access to property '_dragging_monster'`。
   用 `Get-ChildItem -Recurse` 或 ripgrep 重新核过：19 个字段里只有这一个被漏掉，补上代理即恢复。
4. 只被外部读的代理会触发 `unused_private_class_variable` 警告（GDScript 只看本类内引用）。
   加 `@warning_ignore("unused_private_class_variable")` 并写清"为什么声明了却没用"，比留一堆
   黄色警告好用 —— 警告太多时真错误会被淹掉。

`creative.gd` 现在 2923 行：状态搬走了，但多了 10 个兼容代理（外部仍按旧名读写）。
P4 删掉代理后才会真正变小。

**测试是约束，不是障碍**：P1–P3 期间保留 `creative` 上的转发方法（一行 `return _layout.xxx(...)`），
测试先不动；P4 一次性把测试指向新入口，然后删掉转发层。这样每一步都能独立验证。

## 不做的事

- 不引入 `Manager` / `Service` / `Controller` 之类的新抽象（见 `doc/代码规范.md` 第 2 条）。
- 不为"以后可能要"预留端口；端口只为当前存在的可撤销操作存在。
- 不换掉 `action_requested` 这套字符串动作总线——它已经让视图和文档解耦，是可用资产。
- 不在同一个提交里既拆文件又改行为。
