# 文件组织

每个模块自带 `doc`，与 `src` / `asset` 并列。根 `readme.md` 只当目录。

- 脚本进模块的 `src`；`tools` 是扁平工具目录，`test` 顶层是验收脚本、`test/tools` 放标定/性能工具。
- 资源和使用它的场景放一起，进模块的 `asset`。
- 模块的 `doc` 只写这个模块自己的事；没有内容的模块不建空目录。

自有文件命名遵循引擎的小写 `snake_case`。例如：`ink/src/ink_runtime.gd`、`actor/portal/src/map_portal.gd`、`ui/map_text/src/map_text_label.gd`。`ui/background` 和 `ui/menu/title_fx` 同样分为 `src` / `asset` / `doc`；标题水面性能探针在 `test/tools/profile_title_water.gd`。

## 顶层

| 目录 | 是什么 |
| --- | --- |
| `root/` | **应用与模拟装配**：唯一主场景管理 `Level` / `UI`；`simulation_runtime.tscn` 统一装配物理步进、碰撞伤害和颜色规则 |
| `map/` | 关卡内容（世界 + 道具 + 玩家实例 + 相机 + 创造模式）与地图资产；不保存通用模拟脚本 |
| `actor/` | 可交互物品与角色：`player` / `canvas` / `nail` / `ink_item` / `gym` / `monster`；玩家及墨水瓶角色资源归 `actor/player`，只有小怪的地图包装与导入资源归 `actor/monster` |
| `ui/` | **玩家看的成品 UI**：`hud` / `esc` / `menu` / `level_select` / `dialogue` / `theme` / 装配场景 `game_ui.tscn` |
| `debug/` | **开发者用的在线工具**：`creative`（创造模式）/ `hud`（调试 HUD + 力观察器） |
| `test/` | **离线断言**（AI 跑）：验收脚本 + `test/tools` 标定工具 + `doc/验收.md` |
| `tools/` | 资产工具：烘焙（`bake_art.gd` / `bake_cli.gd` / `bake_editor.tscn`）、`pixel_editor/`（第三方像素编辑器网页应用）、`deploy_engine_addon.ps1`（把外部引擎的 addon 部署进来）、`validate_project.ps1`（静态校验） |
| `ink/` | 材质与美术层：`asset/`（材质资源）/ `src/`（`pixel_art_layer` 等）/ `doc/` |

## 角色资源的归属

- `actor/player/asset/`：玩家贴图、材质和着色器；墨水瓶角色的部件、表情与抖动帧统一放在 `asset/inkman/`。
- `actor/player/src/`：玩家控制与物理脚本；导入墨水瓶角色的视觉脚本放在 `src/inkman/`。
- `actor/player/inkman_character.tscn`：墨水瓶视觉场景；`inkman.tscn` 只保留视觉包装，不挂小怪脚本或小怪分组，也不新增可放置小怪。
- `actor/monster/imported/`：只保留炸弹狂、盾兵、小兵等小怪的源资源包。包内原有结构暂保留，避免丢失源素材组织关系；不能再把玩家资源放进这里。
- `actor/monster/asset/`：小怪通用血条素材与着色器；`src/` 放小怪通用逻辑；`doc/attacks.md` 和 `doc/health_bar.md` 分别说明攻击与血条。

移动资源时要同步更新场景、脚本、文档及 `.import` 中的路径，并保留 `.uid` 和 `.import` 的资源身份。不要只在文件管理器中移动图片而留下失效引用。

## 通用模块与功能说明

- `actor/blueprint/src/`：蓝图数据编解码与存储；说明位于 `actor/blueprint/doc/blueprints.md`。
- `ui/blueprint/src/`：蓝图手册、预览与放置交互；不与蓝图数据层混放。
- `actor/effects/src/` / `asset/`：角色共用特效逻辑 / 着色器。
- `ui/transition/src/` / `asset/`：切屏与加载逻辑 / 转场着色器。
- `debug/player/src/inkman_demo.gd`：墨水瓶表情、墨量与抖动的开发演示面板脚本，不属于玩家运行时控制逻辑。
- 传送门说明在 `actor/portal/doc/portal.md`；安全脱困在 `actor/player/doc/safe_unstuck.md`；画布邻近交互在 `actor/canvas/doc/canvas_proximity.md`；编辑撤销在 `debug/creative/doc/editing_undo.md`。

全局 `doc/` 仅保留跨模块规范、审计与调研资料。地图模块的现有目录和测试场景按用户要求保持原样。

## debug 与 test 的分工

两者**功能像但用途不同**，不要合并：

- `test/`：**离线断言**。headless 跑脚本，`_check` + 退出码，谁都没人看画面。给 AI / CI 用。
- `debug/`：**在线工具**。游戏跑起来后自己开（Tab 切调试 HUD、创造模式、F1 低帧录制）。给人用。

依赖方向：`test/` 引用游戏；`debug/` 被关卡引用（调试 HUD）或独立跑（健身房在 `actor/gym`）。

## 场景装配

```
root/root.tscn   ← 唯一主场景（project.godot 的 run/main_scene）
├─ Level  ← 关卡场景（选完关才挂）：世界 + 道具 + 玩家 + 相机 + SimulationRuntime + Creative + Gym
└─ UI     ← 换屏只换这里：[ui/menu] ─开始→ [ui/level_select] ─选关→ [ui/game_ui：Hud(layer=1) + Esc(layer=20)]
```

`SimulationRuntime` 的资源和脚本统一放在 `root/`，但节点由关卡实例化为 `PixelWorld` 的直接子节点；切换关卡时模拟状态随关卡一起释放和重建。详细边界见 `root/doc/Root与Simulation.md`。

关卡里另有 `debugHUD`（`debug/hud/debug_hud.tscn` 的实例）—— 它是关卡的调试覆盖层，所以随关卡一起换。

关卡里的 `Gym`（`actor/gym`，和 `SmallCanvas` / `MapCanvas` 平级）同理：跟着关卡一起换，见 `actor/gym/doc/健身房.md`。

## 关卡的判据

`ui/level_select` 递归扫 `res://map` 下的 `.tscn`，**只收"场景里有一个叫 `Player` 的节点"的**——
地形件（一块烘好的静态图）没有 Player，自动排除。创造模式 F5 存出来的关卡进哪个目录都进列表。
