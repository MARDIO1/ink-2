## 2. 游戏层缺陷（本仓库要改的）

### 2.1 【高】免墨水模式的账本只在"进入"时清，退出后擦墨会凭空生墨
- `canvas_surface.gd:520-527`：`ink_free` 的 setter 只在 `value == true` 时调 `_refund_all_ink()`；`value == false` 时**只赋值**。
- `canvas_surface.gd:551-559`：`_bump_ink()` 开头 `if delta == 0 or ink_free: return` —— 免墨水期间的落笔/擦除**完全不进画布自己的账**。
- `canvas_surface.gd:563-576`：`_flush_ink()` 把负 delta 交给 `health.add()`。
- `debug/creative/src/creative.gd:131-134`：进/出创造模式对两块画布各调一次 `set_ink_free()`。
- 复现路径：进创造模式（免墨水）画一片 → 退出（账本仍是空）→ 在同一块画布上擦这些像素 → 每像素 `_bump_ink(before, -1)` 让账本变负 → `_flush_ink` 往瓶子 `add()` → **瓶子凭空涨墨**。这与 `:518` 那句"画、擦、重绘都不动墨水"直接矛盾。
- 最小修法：setter 的 else 分支顺手清账（`ink_px_by_material = {}`、`_pending_ink = {}`）。

### 2.2 【高】灰墨密度两套表打架
- `map/main.tscn:31` 的 `densities_fallback` 里材质 4 = **2.0**，经 `PixelWorld._density_of()`（`pixel_world.gd:567-570`）给**刚体烘焙**（`:451`）与 `refresh_mass` 供数。
- `pixel_world.gd:337-351` 另外把每个材质的 `m.density` 写进 `PWorld.material_density`；`Ink/asset/grey1.tres` **没有** `density` 行 → 取默认 1.0 → `material_density[4] = 1.0`。
- 分片/破坏后的重建走 `PWorld.density_callable()`（`pworld.gd:716/731/2679/3266/3425`）→ 用 1.0。
- 后果：同一块灰墨，本体质量按 2.0 算，被打碎一次就按 1.0 算（质量、惯量、破坏预算全不连续），且不报错。
- 最小修法：`grey1.tres` 补一行 `density = 2.0`（其余材质两表本来就一致：黑 1.0、身体 1.40338、手 0.1344、高光 0.0、隐形 1.0）。

### 2.3 【中】两个旋钮的注释与值**相反**（同一次提交的 message 也证明是反的）
- `bottled_ink.gd:70-74`：`## ⚠️ 别用 1.0：容器被填满时没有液面` —— 紧跟着 `var max_fill := 1.0`。
- `bottled_ink.gd:96-109`：`## ⚠️⚠️ 不能往小调 —— 试过 150 …结果是液面永远静止不下来`、`## 落到底的时间 …600 -> 0.44 秒` —— 紧跟着 `var gravity_px := 150.0`，且 `player.tscn` 没有覆盖它（运行时生效值就是 150）。
- `git show 34bd9ed` 的 message 写的是 `gravity_px 600 -> 150（原来液面静不下来；600 时覆盖率只有 62%）`、`max_fill 0.9 -> 1.0（按 100% 填充，静置覆盖 85.9%）` —— **是这两段注释没跟着改**。
- 后果：本项目"注释即规格"，下一个读它的人（或 AI）会照注释把值改回 600 / 0.9，把已经修掉的 62% 覆盖率与"液面没有参照物"重新引入。
- 最小修法：两段注释各改写一句当前值的原因（算式可留，反向结论要删）。

### 2.4 【中】卡顿看门狗无条件 quit(2)
- `debug_hud.gd:92-110`：`_watch_hang()` 在 `_process` 里**与 F1 录制无关**地每帧检查：连续 `hang_frames=2` 帧超过 `hang_frame_ms=500` 就写现场并 `get_tree().quit(2)`。
- 触发面不止失控物理：进关卡那一帧（实例化 + 2048×1024 画布贴图 + 首次渲染）本来就可能连出两个长帧；F5 导出（2M 像素 solidify）同理。
- 最小修法：把看门狗挂到"正在录制低帧"或显式开关上；至少在换屏/关卡加载期间不计数。

### 2.5 【中】大地图上的逐像素长任务
- `canvas_solid.solidify()`（`canvas_solid.gd:39-45`）对整张画布逐格调 `surface.material_at()`（每格一次 `get_pixel` + 对两种墨水与钉子做 Color 比较）：`map/main.tscn:45` 与 `map/asset/map.tscn:65` 都是 `canvas_size = (2048, 1024)` → 单次 200 万格。
- `canvas_surface._bucket_fill()`（`:450-504`）每次都 `black_image.get_data()`（8MB 拷贝）+ `seen.resize(w*h)`（2MB）+ 可到 200 万格的 DFS，且**免墨水模式也照旧按瓶里余额拒绝**（`_ink_room()` 不看 `ink_free`，`:535-539`）→ 创造模式里灌一个大于 2 万像素的封闭区会被"墨水不足"挡掉。
- 这两条只在玩家点 Generate / F5 导出 / 用桶时付，常规帧不受影响（`test_collision_damage` 实测 120 固定步 83.69ms 属正常）。
- 最小修法：桶填充在 `ink_free` 时跳过余额检查、`seen` 按需分配；solidify 直接查 `get_data()` 的字节，别逐格走 Color 匹配。

### 2.6 【中】钉子外观每帧全量查像素（规范 §9）
- `nail.gd:55-61` 的 `_anchor_alive()` 在 `_physics_process` 里对每枚钉子遍历 `body.shapes` 逐个 `get_pixel`；钉子多时 O(钉子 × 形状)/帧。
- 最小修法：钉子像素在身体的 `tags["static_anchor_points"]` 里已有集合（`collision_damage._update_anchors()` 一直在维护），直接查集合即可。

### 2.7 【低】_input 早于 GUI：点 HUD 也会落笔
- `canvas_surface.gd:52-56` 与 `canvas.gd:360` 都用 `_input`，而派发顺序是 `_input` → GUI → `_unhandled_input`。相机跟随时画布可能正好落在 `ui/hud/hud.tscn:59` 的右上退出按钮下面 → 点一次退出，画布上多一个点。
- 最小修法：落笔前判 `get_viewport().gui_get_hovered_control() == null`，或把绘制挪到 `_unhandled_input`。

### 2.8 【低】运行时写 res://
- `canvas_surface.gd:598-614`（F5/F9 存读）、`creative.gd:170-171`（导出关卡/整图）、`debug_hud.gd:37`（F1 低帧日志写 `res://test/*.jsonl`）。编辑器里能用；导出成 PCK 后 `res://` 只读。`test_live_input.gd` 这次已经改到 `user://` 了，其余三处没跟上。

### 2.9 【低】关卡列表依赖运行时扫盘（未在导出包验证）
- `level_select.gd:44-59` 用 `DirAccess` 递归扫 `res://map`，靠"场景状态里有名为 Player 的节点"（`:63-72`）筛真关卡。编辑器里实测可用（日记记 `LEVELS: [map.tscn, main.tscn]`）；导出时文本资源会转二进制/带 remap，**要做成品前必须在导出包里实测一次**，或改成显式关卡清单。
