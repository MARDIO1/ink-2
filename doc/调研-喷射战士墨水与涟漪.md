## 0. 结论速览

1. **Splatoon 的墨水渲染实现，任天堂从未公开**。核心专利族（5980266 / 6283072 / 6543361 / 6561155）
   全部是**玩法与网络同步**，没有一件覆盖渲染。官方访谈、GDC 演讲也零渲染内容。**[官方]**
   唯一硬的一手线索是**拆包出来的武器墨水质参**：墨水不是连续笔刷，而是**离散"涂章"**
   （着弾塗り / 中間塗り / 足元塗り），章形沿飞行方向**拉伸**，半径按距离三档分级。**[拆包+逆向]**
   Splatoon 1 的内存变量名也被逆向出来了（mSplashPaintRadius / mPaintFarRadius / mSplashSplitNum /
   mCreateSplashNum / mRepeatFrame / mInitVel），与 3 代参数一一对应 ⇒ **「涂章」模型从 1 代起就没变过**，
   而且**有一套完整的逆向公式**（见 §2.3）。
   ★ 更关键的一条：**涂地占比是「落章时把面积累加进 CPU 计数器」，不是回读画布**（见 §7）。
2. **观感完全可以复刻，而且开源界已经做到位了**。最完整的单一参考是
   [inkwave](https://github.com/jaydendavisnc/inkwave)（MIT，438★，three.js 4v4 涂地对战）：
   单张图集 RT + 通道编码 + 湿/干 + 解析式涟漪 + 增量覆盖率统计，全套都在 `src/world/paint.js` 与
   `src/world/inkShading.js` 里。**建议把它当作本项目的头号参考。**
3. **3D 侧的"数据存哪"只有五条路**：UV 图集 RT、世界空间 unwrap 图集、3D Texture、屏幕空间、
   贴花几何。**3D Texture 与顶点色涂装没有任何公开实现**；UE 官方明确不建议用 RVT 做动态涂装。**[源码/官方]**
4. **"墨水有厚度"不是几何**，而是 **覆盖率掩码当高度场 → 求梯度 → 微扰法线 + 边缘提亮 + 接触阴影**。
   Splatoonity 用 3-tap SDF 梯度，inkwave 用三次 B 样条解析梯度。**[源码]**
5. **涟漪不要做模拟**。inkwave 的做法是**一张 24 槽的解析涟漪表**（位置 + 出生时间 + 振幅/波长/速度/寿命），
   shader 里直接求值；这是零成本、可控、可去重的方案。**[源码]**
   若确实需要**互相干涉、绕障碍**的水波，才上波动方程高度场：`h' = 2h − h_prev + λ∇²h`，
   二维 λ ≤ 0.5（工程取 0.08–0.25）。**[源码]**
6. **本项目（GL Compatibility）没有 `RenderingDevice`，compute 路线直接出局**；
   但 Godot 4.7 新增的 `DrawableTexture2D` 在 GL 下可用，是本项目唯一的"GPU 直接落笔"通道。**[实测]**
7. **覆盖率统计本项目已经做对了**：`CanvasSurface.ink_px_by_material` 就是 inkwave 那套**增量账**，
   除一下可涂总面积即可，零额外成本。**[源码]**

### 关键实测数字（Godot 4.7.2 / GL Compatibility / RTX 5060 Laptop，本机）

| 操作 | 512² | 1024² | 2048² |
| --- | --- | --- | --- |
| `ImageTexture.update()` | 0.280 ms | **0.912 ms** | 3.581 ms |
| `get_image()` 同步回读 | 0.431 ms | 1.125 ms | 5.192 ms |
| `Image.create_from_data()` | ≈0 | ≈0 | — |

- `set_pixel` ≈ **0.02 µs/px** ⇒ 1024² 全刷一次 20 ms+，**不可接受**；
  `Image.blend_rect` 32×32 → 1024² 只要 **0.0304 ms**（**快 200×**）。
- `SubViewport` 设 `CLEAR_MODE_NEVER` + `UPDATE_ALWAYS`，1024²/2048² 每帧只多 **+0.06 ms**。
- `DrawableTexture2D.blit_rect` ≈ **5.5–6.5 µs/次**：每帧 500 次几乎免费，3000 次 → +16.4 ms。
  60 fps 实用上限 **1500–2500 次/帧**；`get_image()` 1024² = 1.44 ms。
- GDScript 逐像素 CA 全图（2048×1024）**≈65 ms/帧**；精确全图计数 **77 ms**。
- 20 px 粗网格全扫（5356 格）**≈0.2 ms**；256×128 mip 链归约到 1×1 **0.19 ms**。

### 2.3 拆包参数：最硬的一手证据（离散"涂章"而非连续笔刷） **[二手，结构化数据强]**

出处：<https://wikiwiki.jp/splatoon3mix/検証/パラメータ情報/メイン>

每把武器带 `PaintParam` / `SplashPaintParam` / `SplashSpawnParam` / `DrawSizeCollisionPaintParam`：

- **涂地是三段离散"涂章"**：着弾塗り（命中章）+ 中間塗り（弹道中间章）+ 足元塗り（脚下章）。
  这直接推翻"连续笔刷轨迹"的直觉，也解释了墨迹为何"一坨坨堆起来"。
- `DepthScaleMax/Min`（+ BreakFree / Straight 两套）= **涂章沿飞行方向的前方拉伸系数 × 涂半径**
  ⇒ 墨迹是**拉长的椭圆**；直进帧与非直进帧用不同值。
- `WidthHalfNear/Middle/Far` + `DistanceNear/Middle/Far` = 按距离三档的涂半径。
- `SplashSpawnParam`：`SpawnNum`（每循环中间涂最大数）、`SpawnBetweenLength`（中间涂间距）、
  `SpawnNearestLength`（起始距离）、`ForceSpawnNearestAddNumArray`、`SplitNum`（脚底涂循环间隔）。
- `SplashPaintParam`：`DepthMaxDropHeight` / `DepthMinDropHeight` = **按落差的拉伸**。
- **滚筒有 `PaintParam.Depth`**，wiki 注释直译"**按在墙上涂时的高度？**" ⇒ 墨有"高度/厚度"的一手线索。
- 涂半径随时间衰减：`ChangeWidthStartFrame` / `ChangeWidthEndFrame` / `ChangeFrameWidthRate`。
- 充电器 `OnTopRate` = 中间涂章重叠比例；`LastSplashRate*` = 尖端涂半径倍率。

**Splatoon 1 的内存变量名也被逆向出来了**（<https://wikiwiki.jp/splatoon2ch/未整理・未確認情報>）：
mSplashPaintRadius / mPaintFarRadius / mSplashSplitNum / mCreateSplashNum / mRepeatFrame / mInitVel
—— 与 3 代参数字段一一对应，**涂章模型从 1 代起未变**。

**并且有一套完整的逆向公式**（Splatoon 1；变量名来自内存 dump，2ch wiki 整理）：

    飛沫補正 = 1.5 ; 近距離補正 = 1.5 ; 減速度 = 3 ; 落下F = 4
    弾速            = mInitVel - (落下F * 減速度)
    飛沫塗り         = (mSplashPaintRadius * 1.5)^2 * PI/4
    近距離飛沫塗り    = (mSplashPaintRadius * 1.5 * 1.5)^2 * PI/4
    軌跡の個数       = mSplashSplitNum * mCreateSplashNum
    飛沫塗り         = (飛沫塗り*(軌跡の個数-1) + 近距離飛沫塗り) / 軌跡の個数
    着弾塗り(遠距離時) = mPaintFarRadius * (mPaintFarRadius + 着弾時の横方向弾速) * PI/4   ← 椭圆！
    単発塗り         = 飛沫塗り * mCreateSplashNum + 着弾塗り
    塗りポイント      = 単発塗り / 300
    秒間塗り(シューター) = 単発塗り * 60 / mRepeatFrame

**注意「着弾塗り」那一行**：面积 = R × (R + 着弾時の横方向弾速) × π/4 —— **半径被「横向弹速」拉长成椭圆**，
这是「墨迹沿飞行方向拉伸」在公式层的直接证据，与 3 代的 DepthScaleMax/Min 是同一件事。
另外 SplashPaintParam 用 DistanceXZFar/Near（**XZ 水平距离**）判档 ⇒ 涂章判定**以水平面为基准**；
DepthMaxDropHeight / DepthMinDropHeight 按落差调拉伸 ⇒「从高处落到低处」被显式建模。

**对本项目的直接启发**：喷溅应当建模成"**一串沿弹道按间距摆放的、带方向拉伸的涂章**"，
而不是"一笔连续笔刷"。这比连续笔刷更好做随机化、也更好算覆盖率。

### 2.4 中文圈最完整的 UE5 复刻拆解 **[源码（正文已提取）]**

Astroite《SplatoonInk》<https://astroite.com/gamedev/2epshdgh/>（VuePress 客户端渲染，
直接 fetch 只拿到空壳；正文已提取到 `D:\ink-research\si.txt`）。要点：

- 参考工程常用 **5 张 RT**（前/后/左/右/地面）分别记录，对场景结构要求高 → 他改成
  **单张 2000×2000 RGB RT 记录全场景**（类似烘焙 lightmap 展开）。实测一张标准对战地图只用 **~16% 面积**。
- **UV 预处理**：每个 2D 面片按规则统一展开进单位方形（保证纹素密度一致）→ 跟随 Actor 缩放记录 Scale →
  摆放完成后用 **MaxRect 装箱**打图集，记录每片 Offset/Scale。
- Scale/Offset 通过 **Custom Primitive Data** 传给材质实例（兼顾合批与 UGC 编辑自由度，且方便序列化/服务器同步）。
- **笔刷朝向**：命中点 Normal + Tangent 求 BiTangent 建 TBN → 用 Normal 把子弹速度投影到面所在平面 →
  与上一步向量点乘得**旋转角**，保证墨沿弹射方向甩出。
- **掠射角**：由速度与法线算掠射角，与阈值比较取**两套笔刷**（接近垂直用方形纹理，接近掠射用长条纹理），
  绘制时再按角度**拉伸**。
- **斜面流动**：命中后按 Normal 与 Gravity 算斜面角，在一段时间内**反复绘制流动笔刷**，每次沿斜面步进一段距离；
  生成 Handle 记录绘制次数，每帧步进一次，归零移除。（朝向同样求法，只是把 Velocity 换成 Gravity。）
- **材质**：把 RT 采样到的像素值**当作高度** → 相邻像素高度差求法线；预定颜色作 BaseColor；
  再按高度确定颜料范围，**边缘更亮**（颜料堆积观感）。
- **占比统计**：UE 逐像素回读很慢 → 改用 **Compute Shader 并行统计 + 一次 GPUReadback**。

### 3.2 五个仓库的核心机制（逐个说清）

#### (1) inkwave —— 单张图集 + 通道编码 + 解析涟漪 ★★★

`src/world/paint.js`（929 行）与 `src/world/inkShading.js`（302 行）。

**图集编码（RGBA8，按覆盖率预乘）**：

| 通道 | 含义 |
| --- | --- |
| R | 队伍占比（0 = 队0，1 = 队1），"over" 合成 ⇒ **最新的墨在交界处获胜** |
| G | 湿度：每次落墨 = 1，减法 pass 在 ≈6 s 内烘到 0（新墨更亮、更"鼓"） |
| B | 每章的色调 |
| A | 覆盖率，≈3 texel 的平滑剖面，**MAX 混合**（并集；扩散中的墨反复重画是幂等的） |

**混合状态（这是全篇最可操作的一段）**：

```js
blending: THREE.CustomBlending, blendEquation: THREE.AddEquation,
blendEquationAlpha: THREE.MaxEquation,          // ★ A 用 Max → 并集
blendSrc: THREE.SrcAlphaFactor, blendDst: THREE.OneMinusSrcAlphaFactor,  // RGB over
blendSrcAlpha: THREE.OneFactor, blendDstAlpha: THREE.OneFactor,
```

**干燥**：一次 `ReverseSubtractEquation`、`src=One dst=One` 的全屏 pass 在 G 通道上减 `k/255`
（每 1/40 s 减 1/255，≈6.4 s 全干）。它和 splat 在同一 pass 里画，**mip 链每帧只重建一次**。

**图集**：4096² RGBA8，`LinearMipmapLinearFilter` + `generateMipmaps: true` + anisotropy 8，
**每面 padding 8 texel**（≥ 2^maxLod，保证 mip 永不跨面渗色）；面按高度排序做 **shelf packing**，
纹素密度从 30 ppm 起每次 ×0.92 重试直到装下。

**一次喷溅的形态学（全在片元里解析生成，没有模拟）**：
`smin` 做圆滑并集；`sdRay` 做锥形溅射条；主体是 `wob` 调制的圆：

```glsl
float wob(float a, float s) {
  return 1.0
    + 0.12*sin(3.0*a + s*6.2831) + 0.08*sin(5.0*a + s*17.0)
    + 0.05*sin(7.0*a + s*41.0) + 0.03*sin(11.0*a + s*73.0) + 0.018*sin(17.0*a + s*29.0)
    + 0.17*pow(max(cos(a - s*37.7), 0.0), 28.0)        // 两根"手指"状凸出
    + 0.12*pow(max(cos(a - s*53.3 - 2.1), 0.0), 36.0);
}
float fw = max(fwidth(sd), 1e-5);
float a  = 1.0 - smoothstep(-1.5*fw, 1.5*fw, sd);      // 预乘 alpha 输出
```

时间线：主体从 ≈40% 用强 ease-out 泛开 → 溅射条先甩出去 → **卫星墨滴**晚一拍落地（最远的最后落）
→ **细墨点**最后落 → 墙上下缘**垂流**再跑 1.5–3 s。
`kindShape(kind)` 给每种武器返回（溅射条数、卫星滴数、细点数、垂流数），
`REACH` 给每个 kind 的包围盒半径倍率。**最小特征尺寸要 clamp**：`tipR = max(r*0.012, tx*0.45)`（`tx` = 每 texel 米数），否则小墨点会闪。

**关键工程细节：CPU 与 GPU 跑同一个 `wob`**。CPU 用 `blobWobble` 决定 0.25 m 粗网格里哪些格被认领，
GPU 用同一个函数画边 ⇒ **看到的墨边 == 玩法认账的墨边**。`_cpuSplat` 用 `WOB_MAX = 1.5` 当上界扫格。

**新墨压旧墨**：新的 splat 落下时，附近仍在扩散的**对方** splat 会被 `_emitGrowth(g,3,1,false)` 立刻推到终态，
保证"新墨在上"与玩法网格一致。

**涟漪（见 §6.5）**：`paint.ripple(pos, amp, wavelength, speed, life)`，
每次落墨（半径 ≥ 0.15 且附近 0.16 s 内没有更大的涟漪）自动发一个：
`amp = 0.0038 + 0.0036*min(radius,3)`、`wavelength = 0.1 + 0.05*min(radius,3)`、
`speed = 0.85 + 0.35*min(radius,3)`、`life = 0.55 + 0.2*min(radius,3)`。

**覆盖率**：每面一张 0.25 m 粗网格 `Uint8Array`（0 无 / 1 队0 / 2 队1），
`counts[2]` 增量维护，`coverage()` 就是两次除法。`_initGrid` 时把"埋在几何体内的死格"标出来，
`turfTotal` 只数活的**可涂**格。

#### (2) Splatoonity —— 世界空间 key + 通道 min/max ★★★（GPL-3.0，只借思路）

**它把场景的世界坐标、法线、切线、副法线先渲染进一系列 RT**（`WorldPosUnwrap` / `WorldNormalUnwrap` /
`WorldTangentUnwrap` / `WorldBinormalUnwrap`），然后用一个全屏 pass 循环 10 个 splat：

```hlsl
float4 currentSplat = tex2D(_LastSplatTex, i.uv);
float4 wpos = tex2D(_WorldPosTex, i.uv);            // 每个屏幕像素的世界坐标
for (int i = 0; i < _TotalSplats; i++) {
  float3 opos = mul(_SplatMatrix[i], float4(wpos.xyz, 1)).xyz;   // 进 splat 的 [-0.5,0.5]³ 投影盒
  if (all(abs(opos) < 0.5)) {
    float2 uv = saturate(opos.xz + 0.5) * _SplatScaleBias[i].xy + _SplatScaleBias[i].zw;  // 4×4 图集格
    float n = saturate(tex2D(_MainTex, uv).x - abs(opos.y)*abs(opos.y));                  // 盒内深度衰减
    currentSplat = min(currentSplat, 1.0 - n*(1.0 - _SplatChannelMask[i]));  // ★ 覆盖对手
    currentSplat = max(currentSplat, n * _SplatChannelMask[i]);              // ★ 写自己
  }
}
return currentSplat * wpos.w;   // wpos.w = 该像素有没有几何
```

**不是 alpha blend，是四通道 min/max** ⇒ 天然支持"双方互相覆盖"且**与绘制顺序无关**。
`wpos.w` 那一步是"按世界覆盖裁掉背景"，**注释明说这是为了准确算占比**。

**覆盖率**：`fragDownsample` 用 16 抽 `smoothstep(0.5±0.01)` 做降采样，
`fragCompile` 把四通道**除以总和归一化** ⇒ 直接得到各队占比；
`autoGenerateMips` 降到 4×4 后 `ReadPixels`，**每 1 秒才做一次**（避免每帧同步 stall）。

**假厚度**：3-tap 求 SDF 梯度当法线偏移，**只作用在边缘**：

```hlsl
float4 s = tex2D(_SplatTex, uv), sx = tex2D(_SplatTex, uv + float2(_SplatTex_TexelSize.x, 0)), ...;
float4 mask = smoothstep((_Clip-0.01)-clipDistHard, (_Clip-0.01)+clipDistHard, s);  // clipDist 由 ddx/ddy 抗锯齿
float2 off = normalize(float3(float2(s.x-sx.x, s.y-sy.x), 0.0001)).xy * (1.0 - maskInside) * _SplatEdgeBump;
float3 worldN = off.x * (tex2D(_WorldTangentTex, uv).xyz*2-1)
              + off.y * (tex2D(_WorldBinormalTex, uv).xyz*2-1);
```

外加平铺法线 `_SplatTileNormalTex` 与 `Smoothness → 0.7` 的湿墨高光。
**世界切线/副法线用贴图而不是顶点属性**，这是它能挂在任意朝向网格上的原因。

#### (3) InkPainter —— UV 图集 + 真高度通道 ★★★

`InkCanvas.cs` 把 base/normal/height 各拷一张 `ARGB32` RT，笔刷通过
`Graphics.Blit(rt, tmp, paintMat)` → `Graphics.Blit(tmp, rt)` **乒乓**（一笔 2 个全屏 pass，
三通道全开 6 个）。高度混合有 6 种模式：`USE_BRUSH / ADD / SUB / MIN / MAX / COLOR_RGB_HEIGHT_A`。

配套 `HeightToNormal` / `HeightDrip` / `HeightFluid.cs` / `TessellateHeightTransform`。
**这是公开仓库里唯一成体系做"墨层厚度"的一套。**

#### (4) mixandjam/Splatoon-Ink —— 逐物体 RT + 体积墨水体

- 每个可涂物体 4 张 1024²（mask / UV 岛 / 扩张 / support）。
- `TexturePainter.shader` 把 mesh 的 UV **直接当 clip 坐标**（`o.vertex = float4(uv*2-1)`，
  `ZTest Off ZWrite Off Cull Off`），靠 `CommandBuffer.DrawRenderer` 画进 RT；
  累加靠"读回旧值再 lerp 写回"，**没有 blend state**。
- `ExtendIslands.shader`：先把 UV 岛画进一张标记图，再对岛外像素做 **8 邻域 max 膨胀 1 texel**，
  否则双线性采样会在岛边漏背景色。**这是 UV 图集路线的刚需。**
- 体积墨水体：`Metaball.hlsl` 球体追踪 + 密度场 `2r³/R³ − 3r²/R² + 1`，中心差分求法线，
  屏幕空间渲染 + Kawase 模糊。

#### (5) 反面教材（明确别做的事）

- **每次落墨都 `get_image()` 同步回读 + 逐像素 GDScript 全扫**（tossudev/godot-splatoon-paint 的
  `score_calculator.gd`）：GPU→CPU 同步 + 逐像素的最慢组合，规模一大必卡。
- **每次落笔后 `ComputeBuffer.GetData()` 同步回读**（powerwash 的 `ParallelReduce.compute`）。
- **CPU `SetPixel` 逐像素写贴图**（UnySplat）。
- **全局 bounding box 当"活跃区域"**（CellularFX 的做法）：涂地游戏里墨洒满全图后退化成全图扫描。

| 方案 | 代表 | 分辨率代价 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **UV 图集 RT** | InkPainter、mixandjam、astroite | 2048² RGBA8 = 16 MiB | 精度与 mesh 复杂度解耦；shader 简单 | UV 接缝/拉伸；**必须做 1–2 texel 膨胀**；纹素密度不均处圆笔刷变椭圆 |

| **贴花几何** | tichise/ink-decal、URP Decal | 近 0 | 一次投射、质量高 | **不持久、无覆盖统计**；只适合小面积点缀 |

（tile 选择与精度问题、动态 brush 成本快速累积），推荐"**局域化 RenderTarget + 批量写入 Canvas Render Target**"。
<https://forums.unrealengine.com/t/read-and-write-runtime-virtual-textures/2690509> **[官方]**

**社区对「画布存在哪」最权威的一条推断**（Unity 论坛 shader 专家 bgolus，post #7/#10）：
「**本质上和 Portal 2 的凝胶一样 —— 把颜色渲进一张低分辨率 RenderTexture，该 RT 用场景的 lightmap UV 展开；
再用噪声扰动采样以掩盖低分辨率**。」技术血脉出自 Valve GDC 2011 Alex Grimes *Nonstandard Textures*；

## 5. 一次喷溅的 TA 细节（可直接抄的参数）

### 5.1 离散涂章 vs 连续笔刷

- **Splatoon 是离散涂章**（拆包证据 + 三段：着弾/中間/足元）。
- inkwave 把 kind 分成 8 种：`shot / line / blast / bomb / trail / drop / roll / speck`，
  并由半径/拉伸自动推断。`REACH = [2.45, 2.1, 2.7, 2.75, 2.3, 1.9, 1.25, 1.35]`，
  墙上下淌额外 `DRIP_REACH = 3.9`。
- **生长时间**：`dur = 0.085 + min(0.22, radius*0.075)`（越大越"重"）；
  墙上 `dripDur = 1.1 + min(2.2, radius*1.5)`；垂流进度用 `1 − (1 − t)^2.2`（黏：先快后爬）。

### 5.2 掠射角决定笔刷形状（astroite）

入射方向与法线的夹角 → 取两套笔刷（近垂直用方形、近掠射用长条）→ 绘制时按角度**再拉伸**。
inkwave 的做法更简单：把命中点沿**运动方向**做反向压缩

```glsl
float a = dot(p, dir); vec2 perp = p - a*dir;
float s = a > 0.0 ? 1.0 + sa : 1.0 + 0.25*sa;   // 前方拉长，后方只拉 25%
p = perp + dir * (a / s);
```

滚筒是另一类：不用 blob 用**直边带段**（`BAND_L=0.55 / BAND_W=0.62 / BAND_R=0.1` × 半径），
两侧加正弦波纹。

### 5.3 抗锯齿与最小特征

`float a = 1.0 − smoothstep(−1.5*fwidth(sd), 1.5*fwidth(sd), sd)`，输出**预乘 alpha**。
所有小特征半径都要 `max(..., tx*0.45)`（`tx` = 每 texel 米数）。

## 6. 涟漪与交互水面

### 6.1 统一方程与稳定性

四种公开实现（Unity RT ping-pong / Godot SubViewport 互读 / GDWaterKart compute / Crest）都是同一式子的改写：

```
h^{n+1} = 2h^n − h^{n−1} + λ·∇²h^n,     λ = (c·dt/dx)²
∇²h ≈ h[i+1,j] + h[i−1,j] + h[i,j+1] + h[i,j−1] − 4h[i,j]
```

- **二维 5 点拉普拉斯 + 蛙跳：λ ≤ 0.5**（λ = 0.5 时最高频模态不衰减也不放大，会积噪声；> 0.5 指数发散）。
  一维是 λ ≤ 1，**别混用**。工程上取 **0.08–0.25** 最省心。
- 真实实现的取值：Crest λ ≈ 0.49（Courant 0.7）、Unity 样例 0.1（damping 0.975/帧）、GDWaterKart 0.09。
- **8-bit RT 会静默衰减**：Unity 版必须加 `−0.5/255` 的 round adjuster，否则用 `RGBAHalf/RFloat`。

### 6.2 工程完成度最高的参考：Crest（MIT）**[源码]**

<https://github.com/wave-harmonic/crest> —
`Shaders/Resources/UpdateDynWaves.compute`、`Scripts/LodData/LodDataMgrDynWaves.cs`、
`Scripts/LodData/Settings/SimSettingsWave.cs`、`Shaders/OceanInputs/Resources/DynWavesSphereWaterInteraction.shader`。

**它存的是（高度, 速度）而不是（h, h_prev）**：`RWTexture2DArray<float2>` + `R16G16_SFloat`。

```hlsl
float vtp = vt + dt*c*c/(gridSize*gridSize) * (fxm + fxp + fym + fyp - 4.0*ft);
vtp *= 1.0 - min(1.0, _Damping * dt);
vtp *= weightEdge;                     // 边缘羽化，防反射/拖影
float ftp = ft + dt * vtp;
ftp *= weightEdge;
if (!isfinite(ftp) || !isfinite(vtp)) { ftp = 0.0; vtp = 0.0; }   // 跑 1 小时后会偶发坏值
```

四条纯收益的设计：
1. **双通道（h, v）**：阻尼可以按"每秒"给；速度通道天然适合"注入冲量"。
2. **波速按波长推**：`c = sqrt(wavelength*g/2π)`，`wavelength = 2*gridSize`，
   再按 CFL 硬夹 `c = min(c, Courant*gridSize/dt)`。用户只调 0–1 的 `_courantNumber`。
3. **每秒固定 60 次子步**（`_simulationFrequency`），一帧内补多步 ⇒ 掉帧不改变波速。
4. **边缘软羽化** `weightEdge = lerp(0.95, 1.0, saturate(distToEdge/0.1))` + `isfinite` 兜底。

默认值：LodDataResolution **384**/级联（强制 16 的倍数）、线程组 8×8、`_damping = 0.05`、
`_courantNumber = 0.7`、`_attenuationInShallows = 1`、`_horizDisplace = 3`、`_displaceClamp = 0.3`。
交互球：`_radius=1 / _weight=1 / _weightUpDownMul=0.5 / _innerSphereMultiplier=1.55 /
_innerSphereOffset=0.109 / _velocityOffset=0.04 / _compensateForWaveMotion=0.45`。

### 6.3 物体怎么"注入"水波 —— 最反直觉的一条

| 方式 | 做法 | 观感 | 出处 |
| --- | --- | --- | --- |
| 单点脉冲 | 输入图 1 个白像素 / `h[x,y] += A` | 一圈理想圆环，像石头落水；移动物体是断续的点 | UnityVFX-InteractiveSurface |
| 圆盘图章 | `h = max(h, A*(1−d/R))` 或 smoothstep 覆盖 | 尺寸可控的鼓包；`max` 而非 add ⇒ 连续多帧不累积爆表 | GDWaterKart、Namey5 |
| **SDF + 带限阶跃** | `f(a,x) = ax/(1+a²x⁶)`，`a = 1.67/λ_min`，球内反号抵消球外力 | **唯一在任何分辨率/尺度下都不"长成怪形状"**的做法 | Crest `DynWavesSphereWaterInteraction.shader` |
| 网格足迹 | 把物体网格画进速度场，逐顶点按法线与速度夹角算推出量 | 船首/角色轮廓完全正确 | Crest `DynWavesObjectInteraction.shader` |

**★ 最关键的经验：注入"速度通道"和注入"高度通道"观感完全不同。**
Crest 的注入 shader 输出是 `half4(0, accel*_SimDeltaTime, 0, 0)` —— **只写 v 通道，Blend One One 累加**。
这样一次接触先产生速度、下一帧才变成位移，涟漪是"从物体向外对称扩散的环"。
**直接改 h 会得到一个尖刺然后炸出高频环。**

### 6.4 大水面与局部涟漪如何合成（Crest `ShapeCombine.shader`）

**"大海"和"涟漪"不是两套水面，而是一张位移图的两项之和**：`result.y += waveSimY`，
再由高度梯度**反推水平位移**放大成可见的尖锐波纹：

```hlsl
float2 dydx = (float2(waveSimY_px, waveSimY_pz) - float2(waveSimY_nx, waveSimY_nz)) / (2.0 * texelWidth);
float2 dispXZ = _HorizDisplace * dydx / wavevector;
dispXZ = clamp(dispXZ, -texelWidth * _DisplaceClamp, texelWidth * _DisplaceClamp);   // 防自交
```

法线由**合成后**的位移场做有限差分，`cross(...).y` 夹到 ≥ 1e-4 防 NaN。
本项目若做 2D，等价做法是：**大尺度 = 背景 UV 滚动/正弦叠加；局部 = 涟漪高度场 → 求梯度 →
一半做像素对齐的 UV 折射偏移，一半并入墨水层法线/高光。**

### 6.5 2D 像素场景的做法

1. **SubViewport 互读自动 ping-pong**（Namey5/godot-interactive-water，MIT）：
   `SubViewport "WaterSimulation"` 里的 `TextureRect` 指向子 `SubViewport "DoubleBuffer"` 的
   `ViewportTexture`，子视口再指回父视口 —— **互读即自动乒乓，不需要手动 swap**。
   该仓库 README 自陈三个坑：① 被主渲染循环绑死，无法手动 30 Hz 定步长；② 分辨率相关，换分辨率参数全废；
   ③ 可调性差。**本项目是像素风、分辨率固定 → 坑 ② 反而变成优势。**
2. **像素风额外要点**：涟漪场分辨率取游戏内部分辨率的 **1/4–1/2**（别用窗口分辨率）；
   模拟 shader 必须 `filter_nearest`；高度**量化到 1/16 或 1/8 台阶**避免亚像素抖动导致像素"爬行"；
   折射偏移必须 `round()` 到整像素。
3. **纯 sprite 兜底**：预渲染 8–16 帧同心圆环，按 `life` 播 `AnimatedSprite2D`，加色混合。
   零成本，但环不互相干涉、不绕障碍 —— 只适合一次性表现。**（工程建议，未找到权威出处。）**

### 6.6 Splatoon 的"墨水涟漪"：查无实据，但 inkwave 给了解法 ★

- 三语检索（Splatoon ink ripple / スプラトゥーン インク 波紋 / 喷射战士 墨水 水面 波纹）
  **没有任何公开实现细节**；CEDEC 讲演资料未公开 PDF。
  且 Splatoon 里**墨水落水即失效**（水面不可涂），不存在"墨水面上的波"这个机制。
  **结论：不要指望抄 Splatoon 的墨水涟漪。**
- **inkwave 的解法（建议直接照搬）**：一张 **24 槽解析涟漪表**，
  每槽 = `(xyz 位置, 出生时刻)` + `(振幅, 波长, 速度, 寿命)`，shader 里按
  `age = clock − birth` 直接求值（`sin` 环），**完全不做模拟**。

```js
ripple(pos, amp = 0.006, wavelength = 0.14, speed = 1.2, life = 0.7) {
  let d2 = 0; const vp = this.viewPos;
  if (vp) { const dx = pos.x-vp.x, dy = pos.y-vp.y, dz = pos.z-vp.z; d2 = dx*dx+dy*dy+dz*dz;
            if (d2 > 38*38) return; }                       // 远处直接丢弃
  const score = amp / (1 + d2 * 0.012);                    // 重要度：大 × 近
  let best = -1, bestS = Infinity;
  for (let i = 0; i < RIP_N; i++) {                        // 优先占空槽；否则淘汰最不重要的
    const o = i*4, age = this.clock - this.rip[o+3], L = this.ripP[o+3];
    if (age >= L || age < -1) { best = i; bestS = -1; break; }
    const s = this._ripS[i] * (1 - age/L);
    if (s < bestS) { bestS = s; best = i; }
  }
  if (best < 0 || bestS > score) return;
  ...
}
```

  另外 `_rippledNear(pos, radius)` 做**去重**：0.16 s 内、范围内已有一个不小于本次振幅 70% 的涟漪就跳过。
  **没有这个去重，滚筒一笔会把墨面变成雨点。**
- **游泳尾迹（swimWake.js）**：最多 4 个游泳者（本地玩家永远优先，不够就抢最远 bot 的槽），
  每人 12 点轨迹（每 ≈0.75 m 记一点，`LIFE = 1.15 s`，断开用 `BREAK = −9` 标记，
  传送/重生/上岸必须插断点）。
  shader 把**每一段轨迹变成一圈扩散涟漪**（包络张开成 V 形尾迹），
  并在潜入的身体上顶起一个**光滑的鼓包**（`uSwimH = 头顶 + k`，`uSwimF = 前向 + 速度系数`）。

## 7. 涂地占比统计

| 方案 | 成本 | 出处 |
| --- | --- | --- |
| **增量计数**（推荐） | O(1)/格 | inkwave：`counts[2]` + `turfTotal`，`coverage()` = 两次除法 |
| 粗网格全扫 | 5356 格 ≈ **0.2 ms** | doodle-slam：20 px `Int8Array`（−2 障碍 / −1 未涂 / 0..3 队） |
| mip/reduce + 低频回读 | 256×128 → 1×1 **0.19 ms** | Splatoonity：16 抽 smoothstep 降采样 + 归一化 + mips + 4×4 `ReadPixels`，**每秒一次** |
| 精确全图 GDScript 计数 | **77 ms** | 只能结算时用 |

**分母必须是"可涂格"**：排除障碍格与埋在几何体内部的死格（inkwave 的 `dead[]`、
doodle-slam 的 `grid[i] === -2`）。HUD 低频更新（inkwave `sampleHz: 5`）。

**★ Splatoon 的占比不算画布，而是「落章时把面积累加进 CPU 计数器」[逆向，硬]**。
两条独立逆向互相印证：

- 塗りポイント = 単発塗り / 300（単発塗り = 飞沫章 × 个数 + 着弾章，见 §2.3）。
- 涂点数 ≈ **面积 / 200**：(射程 × 最大タメ幅) + 先端塗り − 最大タメ幅円 + 足元塗り，再 ÷200；
  实测对得上：スクイックリン 3550 → 17–18 pt、スプラチャージャー 4800 → 23–24 pt、
  リッター3K 6450 → 30–32 pt。

⇒ **每个涂章在生成的那一刻就把自己的面积加进一个 CPU 累加器，胜负只比较双方累计值。**
这同时满足「实时百分比」与「实时涂地 Buff/Debuff」，也是性能上唯一现实的做法 —— **根本不需要读画布**。
（任天堂的**官方**公式仍未公开；以上是 2ch wiki 对 Splatoon 1 的逆向结果。
日文博客「塗り100ラボ」只写研究计划、没有给出公式。**不要引用「按多边形面积加权」「墙面不计」这类无出处的说法。**）

**对本项目的意义**：你们已有的 ink_px_by_material 这个按材质 id 的增量账（§8 P0-1），
和 Splatoon 的做法是同一个东西 —— **落章时记账，不要回头扫画布**。
只有确实要从画布统计（连通分量、材质分布）时才需要 reduce，且必须并行分桶 + 单次回读。

## 8. 对本项目的落地建议

### P0 —— 零风险、立刻可做

1. **覆盖率：用现成的账本。** `CanvasSurface.ink_px_by_material`（`canvas_surface.gd:515`）
   已经是**按材质 id 的增量账**，`_apply_ink_delta`（:560）每笔只结算一次净 delta，
   `recount_ink_px`（:646）是全图自愈口径。**照抄 inkwave 只需再加一个计数器**：
   `turf_total` = 可涂格总数（`_resize` / `clear` / `recount_ink_px` 三处同步），
   然后 `coverage() = 各队像素数 / turf_total` —— 就是两次除法。
   注意 `ink_free`（创造模式，:520）下账要冻住，这与该变量的现有语义一致，别绕过它去加数。
   ★ 这条现在有硬证据：**Splatoon 本身就是落章时把面积累加进 CPU 计数器**（§7），**从不回读画布**；
   你们这套账本与它同构，只是粒度是"像素"而不是"面积"。
2. **涟漪：用解析涟漪表，不要做模拟。** 照搬 inkwave 的 24 槽 + 去重 + 重要度淘汰。
   本项目是 2D 像素，涟漪只作为**墨层 UV 抖动 / 高光位移**，偏移量 `round()` 到整像素。
   **成本 ≈ 0**，且不会有波动方程的抖动/发散问题。
3. **不要上 compute。** GL Compatibility 没有 `RenderingDevice`（`gpu_destruction.gd` 已经验证过），
   `Texture3D` 也没有运行时写入 API。任何"GPU 化"提案先过这一关。
4. **别用 `set_pixel` 批量写。** 用 `Image.blend_rect`（快 200×）或直接构造
   `PackedByteArray` + `set_data`；`pixel_renderer.gd` 的分块脏更新继续用。

### P1 —— 决定"像不像 Splatoon"的部分

5. **喷溅改成"离散涂章串"**（拆包证据）：沿弹道按 `SpawnBetweenLength` 摆放若干涂章，
   每章按运动方向**拉伸**（前方拉长），半径按距离三档衰减，最后落一个放大的"着弾章"。
   这比"沿鼠标轨迹铺笔刷"更符合原作，也更好算覆盖率。
6. **墨边外观走 SDF + 同源 wob**：用 inkwave 的 `wob` 谐波函数（系数见 §5.3），
   **同一函数在 GDScript 与 canvas_item shader 里各算一遍** ⇒ 视觉墨边 == 固化/碰撞墨边
   （这正是本项目"隐形墨水剪影 + 美术层"架构最需要的性质）。
7. **"厚度"用零成本的假厚度**：把覆盖率当高度，取相邻像素差/`ddx ddy` 微扰法线，
   **只在边缘生效**（Splatoonity 的 `(1 − maskInside) * _SplatEdgeBump`），
   边缘提亮 + 朝太阳反方向压一点接触阴影（inkwave 的 `away` 因子）。
8. **湿度通道**：一个字节的"新墨计时"（或每帧衰减），驱动**新墨更亮、边缘唇更高、粗糙度更低**
   （inkwave：`roughness = mix(0.26, 0.14, fresh)`、`inkCol *= 1 + 0.07*fresh²`）。
   这是"刚喷上去的墨"与"干了的墨"的差别来源，也是最容易被忽略的一环。

### P2 —— 只有确实需要时才做

9. **真液体/流淌**：`16×16 chunk + 每块非空格子计数`（sand-slide）先挡掉 90% 的格子，
   再用**质量 0..255** 的 CA（Terraria 式：精确下传 + ±3 格 7 元盒平均 + 残水偏置 `<3 时 −1`），
   每帧预算 5k–20k 格。**不要用布尔占用的落沙格做液体**（必然粘滞/抖动）。
10. **GPU 落笔**：若真需要，`DrawableTexture2D`（4.7 新，GL 下可用，MIT）是唯一路径。
    ⚠ 默认材质是 `blend_disabled`（直接覆盖，笔刷不累加），**必须自带
    `shader_type texture_blit; render_mode blend_mix;` 的 `ShaderMaterial`**，
    且 material 是 `blit_rect` 的**函数参数**而非资源属性。API 标 experimental，注意版本变动。

### 明确不要做

- 每帧 `get_image()` 回读（GPU 同步点，issue #75877 记录过 0.2 s 级卡顿尖峰，且与分辨率无关）。
- 用 `Texture3D` 做 3D 笔刷（Godot 无运行时写入 API）。
- 指望从任天堂专利/访谈拿到渲染方案（没有）。
- 直接抄 **GPL-3.0**（Splatoonity）或**无 LICENSE** 仓库的代码
  （UnySplat、UnityDemo_Splatoon2、tossudev/godot-splatoon-paint、
  alfredbaudisch/GodotRuntimeTextureSplatMapPainting、Terraria 反编译源码）。
  思路可以借鉴，代码不能复制。
