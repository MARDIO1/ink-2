# 烘焙

把像素画源图烘成运行时读的「材质图」`.tres`。

## 为什么需要

`actor/player/asset` 下的 `player_body.png` 等是**给人看的源图**：16px 一格，一格 = 一个游戏像素。
引擎要的是 `Image`（`FORMAT_R8`），**R 通道 = 材质 id**，见
`addons/pixel_destruction/nodes/pixel_shape_2d.gd` 的 `source=PAINT`。
`tools/bake_art.gd` 负责这个转换。

## 关键约束

- **一格取左上角 1 个点**（`tools/bake_art.gd` 的 `analyse()`）。源图必须是逻辑位图的整数倍最近邻放大；16×16 网格里有杂色会被静默判读错。
- **每个 4 邻接连通块必须单独出一个 `.tres`**。`PWorld.add_body()` 会把不连通的形状拆成独立刚体，多块塞一张图角色会散架。画布侧同一原因见 `actor/canvas/src/canvas_solid.gd`。
- 源图背景是**透明**（alpha 0），黑描边是**不透明黑**。判空只能看 alpha，不能看颜色。

## 跑法

CLI，参数在 `tools/bake_art.gd` 顶部 `CELL` / `SOURCES`：

```text
godot --headless --path . --script res://tools/bake_cli.gd
```

GUI：编辑器里打开 `res://tools/bake_editor.tscn`，或 F6 运行（会自己开一个 1280×860 窗口）。预览网格、每块 bbox 与**块编号**（编号配色与报告里的 ■ 一一对应），可改格宽 / 顺时针旋转 / 放大；滚轮缩放、左/中键拖拽平移、「适应窗口」复位；确认后再「写入 .tres」。

## 输出

写到 `res://actor/player/asset/<prefix>_<i>.tres`，并打印每块 bbox 左上角，直接填进 tscn 的 `position`：

```text
player_body -> player_body_*  98x138  实心 4378  连通块 6
  player_body_0.tres  position = Vector2(0, 0)  98x138  3951 格  save=0
  player_body_1.tres  position = Vector2(23, 66)  16x14  115 格  save=0
player_hand_unfold -> player_hand_unfold_*  54x46  实心 625  连通块 3
  player_hand_unfold_0.tres  position = Vector2(0, 0)  54x46  617 格  save=0
  player_hand_unfold_1.tres  position = Vector2(31, 25)  2x4  5 格  save=0
  player_hand_unfold_2.tres  position = Vector2(31, 18)  1x3  3 格  save=0
```

⚠️ 这里的 `position` 是**块 bbox 左上角在网格里的格坐标**（已乘「放大」N），不是像素坐标；`98x138` 是该块输出图的像素尺寸。块顺序按格数从大到小。

写盘时 `prune()` 会删掉本次没再生成的 `<prefix>_*.tres`。

## 改大小

- **改「格宽」CELL**：重新抽样。1 格宽的线稿可能整段消失；改成「格内任一 alpha」则线宽变 2 格、实心变多、质量反而上升。**不要用改 CELL 来缩放。**
- **改「放大」N**：1 格 → N×N 格，无损。质量 ×N²，`player.tscn` / `hand.tscn` 里的 `position` 也要 ×N。
- 想真正换尺寸：让美术按目标格数重新出图，再跑一次。
