# 烘焙

把像素画源图烘成运行时读的「材质图」`.tres`。

## 为什么需要

`actor/player/asset` 下的 `player_body.png` 等是**给人看的源图**：一格 = 一个游戏像素，格宽逐图给（`SOURCES` 第 6 项；bag 原生稿是 4px/格，画布稿是 16px/格）。源图各自怎么来的看它自己模块的 doc（`player_body.png` 是合成稿，见 `actor/player/doc/身体.md`）。
引擎要的是 `Image`（`FORMAT_R8`），**R 通道 = 材质 id**，见
`addons/pixel_destruction/nodes/pixel_shape_2d.gd` 的 `source=PAINT`。
`tools/bake_art.gd` 负责这个转换。

## 关键约束

- **一格取左上角 1 个点**（`tools/bake_art.gd` 的 `analyse()`）。源图必须是逻辑位图的整数倍最近邻放大（bag 原生稿本身就是 4px/格，不用放大）；格内出现杂色会被静默判读错。
- **每个 4 邻接连通块必须单独出一个 `.tres`**。`PWorld.add_body()` 会把不连通的形状拆成独立刚体，多块塞一张图角色会散架。画布侧同一原因见 `actor/canvas/src/canvas_solid.gd`。
- 源图背景是**透明**（alpha 0），黑描边是**不透明黑**。判空只能看 alpha，不能看颜色。

## 跑法

CLI，参数在 `tools/bake_art.gd` 顶部 `SOURCES`（`CELL` 只是没写第 6 项时的默认格宽）：

```text
godot --headless --path . --script res://tools/bake_cli.gd
```

GUI：编辑器里打开 `res://tools/bake_editor.tscn`，或 F6 运行（会自己开一个 1280×860 窗口）。预览网格、每块 bbox 与**块编号**（编号配色与报告里的 ■ 一一对应），可改格宽 / 顺时针旋转 / 放大；滚轮缩放、左/中键拖拽平移、「适应窗口」复位；确认后再「写入 .tres」。

## 输出

写到 `res://actor/player/asset/<prefix>_<i>.tres`，并打印每块 bbox 左上角，直接填进 tscn 的 `position`：

```text
player_body.png -> player_body_*  68x87  实心 3304（高光 1310）  连通块 2
  player_body_0.tres  position = Vector2(5, 37)  58x34  1816 格  save=0
  player_body_1.tres  position = Vector2(0, 0)  68x87  1488 格  save=0
player_hand_unfold.png -> player_hand_unfold_*  36x31  实心 354（高光 0）  连通块 1
  player_hand_unfold_0.tres  position = Vector2(0, 0)  36x31  354 格  save=0
player_hand_grab.png -> player_hand_grab_*  35x31  实心 332（高光 0）  连通块 1
  player_hand_grab_0.tres  position = Vector2(0, 0)  35x31  332 格  save=0
player_hand_unfold.png -> player_hand_phys_*  36x31  实心 354（高光 0）  连通块 1   # 材质 6（隐形墨水）
  player_hand_phys_0.tres  position = Vector2(0, 0)  36x31  354 格  save=0
```

⚠️ 这里的 `position` 是**块 bbox 左上角在网格里的格坐标**（已乘「放大」N），不是像素坐标；`68x87` 是该块输出图的像素尺寸。块顺序按格数从大到小。

写盘时 `prune()` 会删掉本次没再生成的 `<prefix>_*.tres`。

## 高光层

源图里**不是纯黑**的不透明像素 = 高光层，单独烘一个材质 id（`SOURCES` 第 5 项，`0` = 不拆）：

- **逐格材质**，不是整图一个值：同一个连通块里两种材质混着存，所以**形状数量一个不变**。
- 黑描边（纯黑）永远走本体材质。判据是 `col.r == 0 and col.g == 0 and col.b == 0`，
  精确到「纯黑」——透明像素先按 alpha 判掉。
- 高光材质（`actor/player/asset/highlight.tres`，id 5）的密度是 **0**：只画、不进质量
  （质量 / 质心 / 惯量一点不动 = 「只有视觉效果」）。颜色给调色板：
  `actor/player/player.tscn` 的 `Visual.palette[5]`。
- ⚠️ `map/main.tscn` 的 `densities_fallback` 第 6 项必须同步成 `0.0`：`pixel_world.gd` 的
  `_density_of()` 读的就是那张表；对不上这 1310 格格白层就会被按 1.0 算进质量。
- 手**没拆**高光（第 5 项 = 0）：bag 原生稿的手没有非纯黑的不透明格，那点灰混在本体材质 3 里。
- **手的第二张画**（grab）走同一套烘焙，但它挂在 `Hand/Visual` 下只画不物理，见
  `actor/player/doc/手.md`。注意：重跑 `bake_cli.gd` 会把已有的 `.tres` 头部 `uid=` 洗掉
  （`ResourceSaver.save` 的行为），跑完要按 `git diff` 补回那三行。
- **`player_hand_phys`** 是手部**物理剪影**：同一张 unfold 图、材质给 6（隐形墨水，见
  `Ink/doc/美术层与隐形墨水.md`）。画不出来的材质仍然进物理 —— 密度靠刚体上的
  `shape_density_scale` 拉回原值。

⚠️ `prune()` 删的是所有 `<前缀>_*.tres`，所以手工资源**别起成 `player_body_*.tres`**
（撞过一次：`player_body_hi.tres` 被下一次烘焙当场删掉）。

## 改大小

- **改「格宽」（`SOURCES` 第 6 项）**：重新抽样。1 格宽的线稿可能整段消失；改成「格内任一 alpha」则线宽变 2 格、实心变多、质量反而上升。**不要用改格宽来缩放。**
- **改「放大」N**：1 格 → N×N 格，无损。质量 ×N²，`player.tscn` / `hand.tscn` 里的 `position` 也要 ×N。
- 想真正换尺寸：让美术按目标格数重新出图，再跑一次。
