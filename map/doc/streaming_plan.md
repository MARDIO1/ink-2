# Noita 式地图流式加载与动态保存方案

状态：设计，尚未实现。2026-10-14 修订：取消“本关全部常驻”，采用附近加载、远区保存并卸载。

## 参考原则

Noita 的公开资料显示，它把像素模拟划成较小单元，同时用约 512×512 的世界区块组织生成、
实体和存档；相机附近加载、远区卸载，实体记录绝对世界坐标。特殊实体可用 keep-alive 机制
保持相关区块常驻，系统还限制常驻流式区块数量。

本项目采用这些原则，不照搬文件格式和数值。当前 PixelWorld 是自定义刚体世界，
单个 PixelBody 可以跨很多像素，不能像纯网格材料一样直接切走一半。

## 两种尺度

流式区块初始取 512×512 世界像素，负责加载、保存和卸载。这个数值与 Noita 接近，
也便于当前 960×540 镜头用少量邻区覆盖；最终值由本项目实测决定。

物理准备单元要更小。当前扉页完整地图烘焙约 2 秒，10 倍一次性烘焙约 20 秒；
一个 512 区块也可能包含不可抢占的大刚体。编译器需要把允许切分的地形拆成更小物理件，
并统计每件像素、chunk、碰撞矩形和实测提交时间。逻辑区块大小不等于单刚体大小。

## 编辑源与生成数据

作者仍编辑完整地图 `.tscn`。Creative 保存编辑源；另加“生成运行地图”，输出：

```text
map/generated/<map_id>/
├─ level.tscn                    # 小型关卡壳：PixelWorld、玩家、相机和规则
├─ world_index.json              # 区域路径、初始实体索引、版本与出生点
├─ terrain/chunk_x_y.bin         # 初始区块地形数据
└─ entities/entity_<id>.bin      # 跨区/独立实体的初始数据
```

索引只保存字符串路径，不能 preload 整图资源。导出工具显式收录这些动态路径。
生成物不是编辑源；重新生成时提升地图版本，旧运行存档需要拒绝、迁移或新开一局。

静态背景地形只有明确标为可切分时才按区块裁切。可搬物品、桥、杆、机关、关节组合
保持完整实体。作者不手工把边界物品切开。

当前 PixelBody2D.bake 使用节点自身 position/rotation，不应用区块父节点平移。
生成器和加载器必须保存绝对世界坐标，注册前换算为 PixelWorld 坐标；物理节点最终仍由
唯一 PixelWorld 管理。运行中只走增量注册/移除，不能 rebuild 全世界。

## 运行存档布局

```text
user://runs/<run_id>/world/
├─ run.json                       # 地图版本、提交序号、玩家/全局状态
├─ terrain/chunk_x_y.bin          # 只为被修改过的地形区块创建
├─ entities/chunk_x_y.bin         # 该归属区块的完整实体记录
└─ journal/...                    # 临时写入/恢复所需的事务记录
```

未修改区块直接从 `map/generated` 载入，避免第一次经过就复制整块。修改过的地形保存当前
材料/像素数据；不能只保存“爆炸操作日志”，因为操作次序、碎裂和规则升级容易造成重放漂移。

实体记录使用稳定 entity_id，并保存足够恢复的数据：类型/源资源、绝对位置、旋转、速度、
像素形状与材料、标签、机关状态、健康、父子和关节关系。无节点的 PBody 碎片同样必须记录。
`.tscn` 不会自动保存这些运行状态；现有 CanvasHistory 将 PBody 转成 InkItem/PackedScene 的
能力可作为首版转换参考，但正式磁盘格式使用只含基础类型的压缩二进制，避免为每个碎片生成 tscn。

## Root 下的最小运行结构

```text
Root
├─ MapStreamer                    # root/src/map_streamer.gd
├─ Level
│  └─ 当前关卡 PixelWorld
└─ UI
```

只新增两个主要运行职责：

| 文件 | 职责 |
| --- | --- |
| root/src/map_streamer.gd | 计算需求、调度加载/保存/卸载、区块状态、实体 ID 去重与 pin |
| root/src/chunk_store.gd | 版本化序列化、压缩、后台文件 IO、临时文件和原子提交 |

另加 `tools/compile_streaming_map.gd` 生成初始数据。不新增 map_chunk.gd、map_manifest.gd、
map_stream_state.gd；普通 Dictionary/Node2D 和 JSON 索引足够。存储与调度分开是为了避免
文件格式、失败恢复和线程 IO 混进每帧距离判断，也便于单独做往返一致性测试。

## 加载、保存与卸载状态机

```text
UNLOADED
  -> READING
  -> PREPARING
  -> COMMITTING
  -> ACTIVE
  -> QUIESCING
  -> SNAPSHOTTING
  -> WRITING
  -> UNLOADING
  -> UNLOADED
```

读取、压缩和写文件放工作线程；Node、PixelWorld、渲染器与物理数组的增删在主线程固定步边界。
先在主线程复制出不可变的基础类型快照，再交给线程压缩写盘。写到同目录临时文件，flush/close
成功后原子替换并更新提交序号；失败时保持区块 ACTIVE，不删除内存对象。

只有 dirty 区块需要写地形。每次变更增加 revision；如果写盘期间又发生变化，旧快照可以落盘，
但区块保持 dirty 并再次保存。卸载要求磁盘 revision 等于当前 revision。

进入 QUIESCING 后不接受新的破坏/生成；已经跨入的活动实体会 pin 或迁移归属。快照完成并成功
提交后才 `remove_body_node` 和释放节点。加载时优先读取运行存档；没有存档才读取初始生成数据。

## 哪些区块加载

MapStreamer 每隔约 0.1 秒或跨过空间阈值重新计算，不按编号连续加载。

- Required：相机可见范围、玩家碰撞安全范围、抓取物和高速实体的 swept AABB。
- Predictive：移动方向上未来一段时间会进入的范围。
- Retained：Required 外再留一圈或 256px 滞回，避免边界反复保存/加载。
- Pinned：玩家、关节岛、剧情、传送目标或显式 keep-alive 实体要求保留的区块。

预加载距离至少为：相机外沿 + 最大速度 × P95 完整准备时间 + 安全余量。
一个任务完成后重新从当前需求集合选择最高优先级，不盲目加载“下一个”。队列空闲时可以准备
一小圈邻区，但受最大加载区块数和内存水位限制。超过预算时优先卸载最远、最旧且未 pin 的区块。

以 512 区块为初始值，960×540 镜头在不同对齐位置可能直接相交至多 3×3 个区块；再加方向预测
和滞回后，目标常驻数应通过实测确定，不能机械复制 Noita 的默认 12。调试 HUD显示 loaded、dirty、
pinned、读写队列、每块内存和最老等待时间。

## 跨区物品

实体只保存一次。归属区块按稳定锚点/质心的绝对坐标计算，文件中仍保存绝对位置；覆盖区块集合
仅用于加载需求。移动跨界时不重新 bake、不换 PWorld，只更新空间索引；在下次安全保存时迁移归属。

任一覆盖区块 Required 时加载完整实体。实体存在期间，其他索引遇到相同 entity_id 只增加引用，
不能再生成一份。实体只有在自己的整个 swept AABB、抓取者和关节岛都离开 Retained 范围后才能保存卸载。

跨区关节把相关实体作为一个保存岛：选一个 owner chunk，整组保存并 pin 它覆盖的区块。
巨型永久机关可以显式 streaming_keep_alive，但必须受调试统计约束，防止多个机关把整图锁住。

可切分地形使用整数半开范围 `[x0, x1)`，边界像素只属于一侧。规则网格切开的连续地形会改变
刚体连通和接缝碰撞，优先在空隙/门口选边界；必须切开的长地面需要高速滑过、接缝落地、爆炸和擦除测试。

## 编辑实体化

Canvas.generate -> CanvasSolid.solidify 当前同步完成连通分量、图像、物理与首次渲染，地图流式加载
不会自动解决编辑卡顿。它改成可取消的准备任务：保留画布预览，分步准备，主线程提交成功后清原笔画；
失败保留笔画。一次实体化仍是一个撤销事务。单个巨型连通物需要 addon 权威源提供可分步准备或
预烘焙恢复接口；简单地“每帧一个 add_body_node”无法中断单个大任务。

## 当前证据与验收

扉页真实地图：约 120 万像素、5185 碰撞矩形，资源解析约 1.0～1.1 秒，物理准备约 1.9～2.0 秒，
地图物理稳定增量内存约 50 MiB。10 倍下界测试：约 1200 万像素、51850 矩形，一次性物理准备
约 19.92 秒，稳定 Godot 静态内存约 598 MiB、峰值约 777 MiB，外部进程工作集约 998 MiB，
静态物理帧平均约 2.27ms。测试没有覆盖窗口 GPU、十份独立资源、编辑撤销和大量碎片。

首版用扉页副本验证：

1. 走远使区块保存卸载，内存回落；返回后像素、位置、速度和机关状态一致。
2. 边界物品、移动物品、抓取、关节岛只存在一份，高速折返不重复生成。
3. 存盘中再次破坏不会丢 revision；模拟写入失败时不卸载原区块。
4. 强制退出后只接受最后完整提交，临时/半写文件不会破坏世界。
5. 高速跨区、传送和复活在镜头看到之前完成准备；不足时由安全边界兜底。
6. 窗口运行记录整帧 p95/p99/max、>16.7ms 帧、工作集/私有内存、加载峰值和保存 IO。

实现顺序：先做二进制往返与原子写入，再做单区块卸载恢复，随后跨区实体和关节，最后接预取、
编辑实体化与正式地图生成。没有通过往返一致性和失败恢复前，不允许自动删除内存中的区块。
