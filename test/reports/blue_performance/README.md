# 蓝墨动态性能审计与修复

2026-10-15。已复现动态缓存退化并修复。首版稳定电路基准不能代表实际游戏性能，
此前验收没有覆盖移动物体和无关碎裂造成的缓存失效。

## 实测环境与范围

- Godot 4.7.2，Windows，OpenGL / RTX 4060 Laptop GPU。
- 加载项目真实 `map/asset/imported/扉页.tscn`，脚本追加双电机和移动接触体。
- 共 14 个刚体、21370 个世界像素存储块、6852 个导电像素。
- 算法阶段每组预热 5 步，采样 60 步；完整调度阶段预热 5 帧，采样 30 帧。
- 完整调度调用真实 `SimulationRuntime._physics_process()`，包括物理推进、规则与渲染数据同步。
  接触体每个固定步移动，另测单帧补跑 4 个固定步，未降低子步或接触更新频率。
- 下表是同步 CPU 耗时；JSON 另存包含等待下一渲染帧的墙钟间隔，不混为同一指标。
- 磁盘场景没有保存用户截图中的蓝色装置，因此这是同关卡构造夹具的对照实验，
  不宣称已直接复验截图中原装置的 7 FPS。

## 根因与修改

1. **缓存失效范围错误。** 原 `_topology_stamp()` 把附近所有刚体的精确相对姿态
   都算入指纹，普通黑色物体移动也会使整个电网失效；范围还是载体刚体的 AABB，
   而非导线自身的 AABB。现在按导线实际范围筛选，只记录可能导电的源、导线、箭头和相关轴系。
2. **无关碎裂也清缓存。** 原 `observe_fracture()` 无论是否涉及蓝色都清空电路指纹。
   已删除这项全局失效；真正的覆盖几何变化仍通过建图失效，源的改变仍通过形状版本检查。
3. **重建时扫描整个世界。** 原 `_contact_graph()` 每次遍历所有刚体的所有像素块寻找红色。
   现在先做范围筛选，再按形状 ID/版本缓存红色范围。单纯移动不再扫描世界像素块。
4. **局部移动重复检查整条导线。** 原检测按整条边界逐点测所有候选源。
   现在每个“导线—电源”对独立缓存，只测其接触包围区域的边界像素；移动生物不重查同体红色。
   这是精确失效条件的调整，没有通过降频或延后断电换性能。

主要代码位于 `ink/src/blue_ink.gd` 的 `_refresh_sources()`、`_topology_stamp()`、
`_source_contact()`、`observe_fracture()`；`blue_wire_layer.gd` 缓存局部边界及边界查询表。
本轮没有修改 addon、物理步长、红色引爆规则或功率收费语义。

截图中的 HUD “CPU”来自 `Performance.TIME_PROCESS`，本实验使用 `Time.get_ticks_usec()`
包围实际调用测量。不能用单个 HUD 数字替代完整固定步和渲染间隔的实测。

## 自测与剩余边界

- 蓝色窗口回归 **55/55**：原有 51 项及新增 4 项动态缓存不变量。
- 新增检查普通物体移动/无关碎裂不重建、不扫描块；新生物接触立即刷新；移动生物只重测一对接触。
- 覆盖燃料不引爆、断线重连、电滑环、保存重载、撤销、部分回收，以及真实鼠标绘制。
- 黄色回归 **45/45**。检查日志未出现脚本错误；测试退出仍有项目已有类型的资源残留告警。
- 首次建图、导线自身大量像素变化、源载体形状改变时仍有真实重建成本；未承诺任意规模恒定耗时。
- 本轮未处理旧红色后坐力失败和旧测试地图路径债务。
