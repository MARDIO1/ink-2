# 白墨 V1

白墨使用已有 InkItem / PixelBody2D / PBody。材质 id 为 10，碰撞 layer 和 mask 均为 0；初速度沿用节点配置，受世界重力、终端速度和速度上限影响。没有摩擦、碰撞冲量或空气阻尼；外部冲量在下一固定步恢复，爆炸和抓取的普通查询不会选中白墨。

白墨独立固化，允许与世界中的实体重叠。分离的白色笔迹共用一个刚体。面积减小时只清 PixelShape 的块并标脏，不重建质量、质心或原生碰撞体，也不做连通性分片。消耗完或离出生位置超过 4096 px 时释放载体。

## 擦除

每个固定步记录白墨和目标位姿。复用 GreedyRects 的精确矩形分解，每个白墨矩形沿路径扫成凸多边形；在目标局部空间逐行生成删除掩码。同一目标同一固定步只有一个合并提交，沿用 SimulationRuntime 的 removal / fracture / sync。

- 黑墨、灰墨、红墨可删除；红墨按已有规则触发下一步爆炸。
- 钉子、普通怪物、手和手臂暂不处理。
- 黄色有效笔画被覆盖后立即移除约束，整根播放死亡动画和释放音，不退款；动画结束后释放节点。
- 玩家通过 `apply_corrosion_damage(amount)` 扣黑墨生命，保留形状，遵守 `damage_enabled`。
- 激活白墨与腐蚀结果不能撤销。发生腐蚀时清理旧画布撤销事务，防止复活被删的实体和黄线。

白墨消耗 = 本轮直接擦除像素数 / 效率。效率默认 `clamp(1 + speed / 300, 1, 4)`，余数跨步累积。黄线销毁按一次事件计数；红墨额外引爆的区域不额外收费。本轮扫掠完整执行后减白墨面积，耗尽时允许最后一轮超额擦除，不做精确的中途停止位置或两两配对。

白墨自身采用固定块序磨损，速度和面积不相互反馈。目标平移和静态旋转按格心覆盖计算；快速旋转目标使用旧/新位姿包络近似，不是完整旋转 CCD。不要将这个近似描述成任意角速度下的严格逐像素证明。

## 文件结构

主规则只有 `ink/src/white_ink.gd` 一个文件，材质为 `ink/asset/white.tres`。没有独立载体类或第二套伤害系统。黄色死亡接口留在黄色管理器，玩家扣血接口留在 player_physics。

引擎 GDScript 增加兼容旧调用的三个小入口：碎屑清理排除列表、初始阻尼 tag 覆盖、节点烘焙时允许保持非连通形状；消融热路径复用原生连通标注、按块删除、提前结束最小面积判断，质量缓存命中时不重复计数。没有修改原生 DLL。重新生成 addon 时需要保留这些改动。

## 测试地图

Godot 中打开 `map/white_ink_test.tscn` 按 F6。它继承现有 main 地图，展示黑、灰、红、黄、玩家五条测试通道。

自动地图验证：

```powershell
& 'T:\GODOT\tool\Godot_v4.7.2-stable_win64_console.exe' --path 'T:\GODOT\ink-2' res://map/white_ink_test.tscn --quit-after 240 -- --white-test
```

规则回归：`--headless --script res://test/test_white_ink.gd`。

2026-10-13 消融优化：160000 px 动态目标上，64×64 白墨横移 16 px、擦除 5120 px，规则加提交从约 31～37 ms 降至约 11～14 ms；7×40 白墨约 6～7 ms。40 固定步连续压力测试（效率提高至 100 以保持白墨存活，重力暂关）验证路径删净、速度不变；窗口模式还计入反应监听、原生步进和渲染同步。五通道地图回归物理峰值约 4.2 ms。具体结果见 `.godot/white_stress_window.log`，机器负载会影响峰值，不保证无限面积或多白墨场景都不卡。

连续窗口压力测试使用上面的地图命令，将 `--white-test` 换为 `--white-stress`。生成贴图先完成再统计消融，仍记录第一笔完整擦除。`WHITE_MAP_WORST` 给出最慢样本的阶段计时；`WHITE_COMMIT_STAGES` 给出删除、连通判定、母体重建耗时（单次调用值，需开启 world.profile_enabled）。没有加入跨帧队列、延后碰撞体或减少擦除采样。
