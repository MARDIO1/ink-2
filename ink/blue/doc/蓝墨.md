# 蓝墨：有方向的能源元胞

2026-10-16 实现。以当前文件为准，旧电网及最宽路径算法已移除。

## 规则与默认参数

- 导线与箭头共享蓝墨账本，各自管理行为。起点在 6 px 内吸附黑色；整支箭头（包括箭头三角形）必须有黑色承载，拖出范围会缩短。任意承载像素被破坏或任意箭头像素被擦除，整支消散，不新建 PBody/焊接。
- 导线是载体上的像素覆盖层，覆盖黑色不增加质量；裸导线参与原有物理形状，强度为黑色一半（压缩 50，剪切 15）。普通擦除仍蓝黑一起擦，黑色被破坏会清除覆盖层。
- 红色只从严格接触的像素发包，输出由实际接触像素数限制；发包时记账，0.1 秒批量正常蚀除，绝不因供能耗料触发红色爆炸。
- 玩家仅在有效抓握关节的抓点附近接入导线；身体/手臂/手擦碰均不供能。可用功率仍为脚与手臂的剩余功率之和，松手后停发，已在途能源与缓冲有有限延迟。Monster 默认未配置 `supply_power`，接触不供能；显式配置该标记的其他生物仍可接触供能。
- 生物能源随传播携带来源标志；含生物能的电机合计推力不得超过玩家身体、手臂、手总重量的 50%，多个箭头共享预算。纯燃料供电不受此限制；混合波头保守地按含生物能处理。
- 默认每 1.0 秒生产一批，速度 600 网格 px/s，最低配置为 100；单包能量随周期同比增加，所以平均功率不变。使用浮点距离余数，每个固定更新可走多格，但逐格同步判断中途断线、分叉、碰撞。四邻接路径的步长为 1 px。
- 每格保留四个方向的能量、波号、波头组和到期时间。只推进活跃波头；同一连续波头横截面共同分配能量，避免粗直线被误当成一堆分叉。
- 不向来路返回；真正分开的局部出口平分，死路消散，同向合并，垂直汇合保留。按波号和来向抑制重复访问，不进行全局连通扫描或路径搜索。
- 单格通过量为 `power_per_width × emission_interval`，窄处多余能源损失，后面变宽不恢复；最低有效能量按出口组判断，避免把微弱边缘像素提前挖成洞。
- 电机沿途先到先取，在自身缓冲和功率上限内消费，剩余继续。缓冲默认容量为 1.05 秒额定功率，按发包间隔平滑释放，停止收到能源后有界过期。长度 L、笔宽 W 的上限为 `F=100000×L×min(1,L/120)²`、`P=100000000×W×min(1,L/120)²`；短箭头同时缩减力与功率，基础收费及逆向做功收费保留。
- 迎面相遇不再自爆或切线：比较相遇位置的两个反向能量分量，保留较大分量的能量和方向，较小分量全部记入损耗。并非相减，也不把两股相加；等值时同载体固定保留右/下方向，跨载体按稳定导线 ID 决胜。同格、相邻格交换、跨刚体接触使用同一规则；不比较整个电网的回环大小。
- 判定先读同步波头并标记败者，再统一扣除，避免哈希遍历次序影响结果。访问记录分四个来向，胜者可穿过败者的反向足迹，但回到自己的同向足迹仍停止；原始到期时间保留。无需电源附近豁免、32 px 注入保护搜索、烧线范围搜索或短路闪光。
- 包寿命默认 20 秒；同帧传输保留方向和年龄，碎裂迁移不重复收费。PackedScene/快照保留导线与箭头源数据，瞬态能源和缓冲不写入保存文件。
- 轴承整个贴图区域可作电滑环，两侧都要有导线；导线可穿过轴承继续延伸，不要求端点落在轴处。滑环作为分叉出口，接收格按自身可走方向展开，避免两侧旋转坐标不同而反向阻塞；离开接收格后恢复普通有向传播。轴/关节失效后电滑环消失。
- 高光使用蓝白亮芯、蓝色光晕、短拖尾；亮芯随能量下降变暗。批量绘制，不给每个包新建 Node、粒子系统或刚体。
- 高光显示参数在 `ink/blue/src/wire_layer.gd`：`highlight_brightness` 默认 2.5，`highlight_core_width` 默认 2 px。运行时可选导线节点在 Inspector 调整；改脚本默认值影响未覆盖参数的导线，不改变供能或推进速度。微弱包保留最低可见亮度。
- Tab 中亮蓝色为每支箭头的实际推力，并列出收到的 MW；金色 `spring~` 为弹簧/阻尼模型估算值，红色余项扣除这些已列出的力后仍可能保留估算误差。进入 F2 暂停力采样并隐藏调试 HUD，退出后恢复之前的 Tab 状态；编辑器内 Tab 留给控件焦点导航。

## 代码在哪里

| 文件 | 职责 |
| --- | --- |
| `ink/blue/src/blue_ink.gd` | 工具分派、墨水记账、生成/回收/撤销/保存、碎裂钩子、配置与运行时入口 |
| `ink/blue/src/wire_layer.gd` | 导线像素、载体跟随、64×64 稀疏显示块、脏块更新、批量高光 |
| `ink/blue/src/motor.gd` | 箭头与锚点、到达能源缓冲、基础收费、力/功率限制和施力 |
| `ink/blue/src/energy_flow.gd` | 电源生产、严格局部接触缓存、红色耗料、玩家预算、电机/滑环接触、原生数据适配 |
| `ink/blue/native/energy_kernel.hpp` | 纯数值有向元胞推进、同步双缓冲、局部出口分组、限流、消费、迎面耗散与迁移 |
| `ink/blue/native/energy_extension.cpp` | 最小 Godot C ABI 注册与二进制数组接口，不处理游戏规则 |
| `ink/blue/native/build.py` | Windows x86_64 MinGW 可复现编译；不依赖修改破坏插件 |
| `ink/blue/asset/blue.tres` | 裸导线物性 |
| `ink/yellow/src/`、`ink/yellow/asset/` | 原黄色机制脚本、端点/轴承图与 shader，保留资源 UID，已更新引用 |

GDScript 逐格处理大量分叉实测达不到目标，因此数值循环单独放入 ink 内的原生模块；没有修改 addons 内部。`gdextension_interface.h` 是 Godot 官方 C 接口头，保留原 MIT 声明。当前交付 Windows x86_64 DLL；其他平台需要另外构建，不能直接据此宣称 Android/Linux 可运行。

## 性能约束

- 不建全网节点/边，也没有最短/最宽路径树。建导线时一次登记像素；之后工作随活跃波头、局部接触和真实修改量增长。新载体/形状替换仍须登记对应像素，初次加载不是零成本。
- 红色候选按已有 8×8 材料块取样，多个远离电源不使用覆盖全屏的大包围盒扫描。
- 发包时验证能源端口仍存在；电机足迹仅在结构/相对姿态变化时重算。
- 运行时不再因电流相遇修改导线或贴图；实际保存/回收才同步序列化导线。原生输出缓冲按活跃数据增长，不按整张导线面积每帧复制。
- 原生波头分组直接在已有活动格上打临时访问标记，避免每个子步为每格新建/释放哈希集合节点；双缓冲保留桶容量。
- 复杂度结论针对固定线宽、相同发包速率的长度增长。大量独立移动载体/轴承的接触更新另有成本，不能用单载体压力图证明任意场景都达标。

## 自测与压力地图

Godot：`T:/GODOT/tool/Godot_v4.7.2-stable_win64_console.exe`。

```powershell
python ink/blue/native/build.py
& $godot --headless --path . --script res://test/test_blue_energy.gd
& $godot --headless --path . --script res://test/test_blue_ink.gd
& $godot --headless --path . --script res://test/test_blue_freehand.gd
& $godot --headless --path . --script res://test/tools/profile_energy_scaling.gd
& $godot --path . --scene res://test/fixtures/maps/blue_energy_stress.tscn -- --bench --case=chaos
```

上面的 `$godot` 指上述 console 程序路径。压力图可直接 F6：1 短线、2 长线、3 混乱走线、R 重建。结果和截图输出 `test/reports/blue_energy/`，详细配置、指标、限制见其中 README。窗口测试使用完整 SimulationRuntime/Rapier、实际电源与箭头、2560×1440，不限帧；5 秒热身后采样 15 秒，1% low 用最慢 1% 帧耗时的均值换算。

双轮演示地图：打开 `map/asset/blue_car.tscn` 按 F6；左轮顺时针、右轮逆时针。两根红色燃料条在台座料槽内，是独立动态刚体，底部消耗后靠重力下落补充接触；使用正常的 `1e8 J/像素`，不再提高储能。两路供电经车架和轮轴电滑环送到箭头，两个台座支点固定车架。生成与保存后复载验收见 `test/tools/build_blue_car.gd`：两个独立红墨刚体、实际像素减少、向下位移、两轮反向转动、零短路及无燃料爆炸。

供能值目前配置在 `blue_ink.gd.energy_per_red_pixel`，不是红墨材质资源：`blue/energy_flow.gd` 生产能源时按此值累计已支付的红像素份额（`fuel[body].credit`），满一个像素后提交删除；`root/src/simulation_runtime.gd.commit_fuel()` 更新实际形状、质量和碰撞，不触发红墨爆炸。`red_ink.gd` 处理红墨受损的爆炸反应。已产生的在途能源位于蓝色原生元胞，电机接收后的剩余能源位于 `blue/motor.gd.energy_buffer`；未消耗燃料总量由剩余红像素表示，没有另存一份红色刚体电池余额。

混乱图含 184204 个导线像素、多电源、12 个箭头、交叉/斜线/闭环，全程不自动修复；验收必须同时满足导线像素完整、持续有活跃电流/电机消费及 1% low ≥50 FPS。测试提高单像素燃料储能，保证持续发包；真实耗料/不引爆红色另由端到端测试覆盖。大块黑色载体设为静态，测试包含实际消费，但不代表大量运动刚体的物理压力。
